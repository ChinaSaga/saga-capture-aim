# CAT 与 MAKCU 统一控制

主窗口右上方新增 **CAT 网络盒子** 按钮。在同一个窗口输入 IPv4 地址、端口（1～65535）和 8 位十六进制 UUID，点击“保存并连接”。连接在后台完成，窗口顶部显示当前使用的设备。

- 参数保存在 EXE 目录的 `CAT盒子.ini`，下次启动自动读取。该文件不提交到 Git。
- CAT 完成命令握手和按键监听握手后才启用；CAT 可用时优先，未配置、停用或离线时使用可用的 MAKCU。
- “停用 CAT”保留已保存参数，并切回 MAKCU；“取消”不修改配置、不退出软件。
- CAT 离线后约每 3 秒重试，在线时每秒一次零位移命令检查应答；MAKCU 保留现有自动检测和重连。
- 移动、轨迹测试、按下、松开、瞄准热键和触发热键共用路由。五个鼠标按键保持原有编号：1 左键、2 右键、3 中键、5/6 侧键。
- 网页的自瞄、准星绑定和扳机共 12 个热键选择框支持 104 个键盘选项。键盘绑定使用 `1000 + CAT/Linux input 键码`，与旧鼠标编号分开；左右修饰键分别选择，当前支持单键。由 CAT 上报键盘状态，不读取运行软件电脑的本地键盘。CAT 离线或切回 MAKCU 时，键盘状态返回未按下。网页与新版 EXE 需要一起更新。
- 切换设备前尝试释放软件按下的按键。网络失联时无法保证即时释放，失败的 CAT 松开命令会在恢复连接后重试；移动和按下命令不补发。

CAT 使用 UDP，命令端口填写盒子的远端端口，本机发送端口和监听端口由系统分配，监听端口会通过协议通知 CAT。需要网络路由可达，并允许应用接收 CAT 的 UDP 报文。不会扫描整个局域网，也不会自动修改防火墙。

CAT 保留原 SDK 的逐命令应答机制，单次命令等待上限为 300ms；正常延迟取决于网络和固件，因此其时延不能视为等同于 MAKCU 串口。原轨迹分段和 0.885ms 等待没有改动。

验证：Release 构建；`tools/test_box_controller.cpp` 本机加密 UDP 模拟覆盖参数校验、错误 UUID、五键映射、物理按键上报、监听失败后重启、设备切换时释放、命令超时、自动回退、自动恢复和停用。该测试不等同于 CAT 实机兼容性验证，固件实际端口行为和鼠标操作仍需实机检查。
