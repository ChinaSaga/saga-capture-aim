# N卡专用推理（TensorRT）

“N卡专用推理”是第三种推理引擎，使用 NVIDIA 显卡和 `.trt` 模型。NCNN、ONNX 入口继续保留，已有配置不自动切换。

## 模型与选择

| 网页选项 | 配置值 | “模型数据”文件夹内的模型 |
|---|---:|---|
| NCNN | 1 | `<模型名>.param` 和 `<模型名>.bin` |
| ONNX | 2 | `<模型名>.onnx` |
| N卡专用推理 | 3 | `<模型名>.trt` |

三个引擎统一从 `EXE目录\模型数据\` 加载识别模型。构建和服务端启动会创建该文件夹；旧版放在 EXE 根目录的模型需移入此处。

例如网页“游戏模型”选择“三角洲行动”，N卡专用推理使用 `模型数据\三角洲行动.trt`。也可使用自己的文件名：将 `新模型名.trt` 放到“模型数据”文件夹，点击“刷新模型”，从游戏模型列表选择“新模型名”，再点击“N卡专用推理”。文件名与列表名称对应，列表不显示扩展名。

模型列表汇总“模型数据”文件夹内实际存在的模型，没有预设游戏名单。同名文件决定当前模型的引擎按钮：配对的 `.param` 和 `.bin` 启用 NCNN，`.onnx` 启用 ONNX，`.trt` 启用 N卡专用。三种模型齐全时三个按钮都可选择；缺少相应文件的按钮变灰并禁止点击。其它模型的文件不会启用当前模型的按钮。

添加或删除文件后点击“刷新模型”，选择其它模型时也会更新按钮。已选模型仍存在时保留选择，否则提示重新选择；当前引擎不适用于所选模型时，需手动选择可用引擎；没有模型或读取失败时禁用列表和三个引擎按钮。

服务端配置沿用系统 ANSI / GBK 编码，模型名称请使用能在该编码中表示的常用中文、英文或数字；包含 emoji 等字符的名称需先改名。

文件夹模型组可在 160～640 的 32 倍数截图档位及同名模型间自动切换，详见 [自适应截图与模型组](自适应截图与模型组.md)。

## 转换步骤

1. 在准备运行的电脑上打开 `x64/Release/ONNX转TRT工具.exe`。
2. 启动后递归扫描转换工具 `EXE目录\模型数据\` 及其所有层级子目录，自动选中全部 `.onnx` 文件，也可点击“选择模型”，使用 Ctrl / Shift 多选。每个同名 `.trt` 自动保存到对应 ONNX 所在目录，无需选择保存位置。工具固定生成 FP16，可直接选择普通 FP32 ONNX；转换只在内存中进行，原 ONNX 文件保留。
3. 点击“开始转换”后会弹出三个选项：“代替并转换”转换全部模型并覆盖已有同名 TRT；“不代替转换”（默认选中）保留已有 TRT，只转换缺少 TRT 的模型；“不转换”取消本次操作。单个失败会继续转换其余文件，结束后汇总成功、跳过和失败数量，详细结果见日志。
4. 确保生成的 `.trt` 位于主程序旁的“模型数据”文件夹，打开网页点击“刷新模型”，选择生成的模型名称，再选择“N卡专用推理”。

“模型数据”文件夹已有同名模型时，先确认是否需要替换；转换失败时不应当把未完成文件作为可用模型。

界面显示“推理精度：FP16”，没有 FP32 或 TF32 选项。命令行默认也是 FP16，无需额外精度参数；可显式传入 `--fp16`，含义相同。转换后验证引擎的输入和输出确为半精度，再保存完成文件。

```powershell
& './x64/Release/ONNX转TRT工具.exe' --input './x64/Release/模型数据/三角洲行动.onnx' --output './x64/Release/模型数据/三角洲行动.trt'
```

动态输入模型可用 `--size 宽x高` 指定尺寸；只有明确需要替换现有输出时使用 `--overwrite`。

TensorRT 模型与生成时的显卡和运行环境有关。换显卡、换电脑或升级相关运行库后，建议从原 ONNX 重新转换；加载失败时，可先切回 ONNX，并查看程序同目录的 `运行日志.txt`。

## 支持范围与依赖

当前接入使用 TensorRT 11.3.0.99、CUDA 13.4。N卡专用引擎按选择加载相关运行库；继续使用 NCNN 或 ONNX 时不要求 NVIDIA 显卡，也不需要启动该引擎。

从源码重建时，执行 `tools/install_tensorrt.ps1` 准备 TensorRT SDK，安装 CUDA 13.4 Toolkit，并设置 `CUDA_PATH` 或 `SagaCudaDir`；SDK 用于编译，运行库随构建复制。安装脚本不安装显卡驱动。运行 N卡专用引擎和转换工具仍需兼容的 NVIDIA 显卡及驱动。

当前支持 YOLOv8 / YOLOv11 的普通目标检测导出：单个 RGB 输入 `[1,3,H,W]`，尺寸不超过 4096，单个原始检测输出 `[1,4+类别数,候选框数]`。不是所有 ONNX 或 YOLO 导出都能使用；带内置 NMS、多输出、姿态、分割等模型不在本轮支持范围。权重需嵌入 ONNX；自定义算子、未内联函数和 Range 算子暂不支持，遇到这些模型会报告转换错误。推荐固定尺寸的标准目标检测导出。

模型名只用于选择同名文件，不会把其它格式自动转换成 `.trt`。FP16 会有舍入差异，需要在自己的模型与画面上比较。

## 性能模式与排错

默认使用 CUDA Graph 和非阻塞事件等待，在读取结果前确保 GPU 已完成。FP16 与 ONNX 的结果可能存在舍入差异；局部推理耗时不能当成采集卡帧率或完整操作延迟。

| 环境变量 | 设置后的行为 |
|---|---|
| SAGA_TRT_BLOCKING_SYNC=1 | 阻塞等待 GPU，以降低 CPU 活动；可能增加延迟 |
| SAGA_TRT_CUDA_GRAPH=0 | 关闭 CUDA Graph，使用普通提交路径 |
| SAGA_TRT_POWER_PROFILE=0 | 关闭同适配器 D3D11 电源配置辅助设备 |
| SAGA_TRT_PROFILE=1 | 开启阶段计时，主程序每 5 秒写性能摘要 |

这些变量在引擎创建时读取，修改后重启程序或重新加载引擎。默认不逐帧写性能日志。变量只作用于继承该环境的进程；在同一 PowerShell 中移除相应 Env: 变量后重启即可恢复默认。

显卡轻负载降频可能增加推理延迟。可按需在 NVIDIA 控制面板为本程序配置“优先最高性能”；这会增加功耗，不是所有机器都需要。源码的 D3D11 辅助设备不提交绘图、不修改全局锁频。

可选 NVAPI 工具通过 tools/prepare_nvapi.ps1 和 NvPowerProfile.vcxproj 构建。工具仅管理自己的专用应用配置，tools/restore_nvidia_profile.ps1 可撤销这些应用配置。改变驱动配置前仍应保存所需的撤销数据。

## 不接采集卡的验证

运行 tools/test_tensorrt.ps1 可检查格式转换、加载错误和 CPU 接口。实际 GPU 模型可用 tools/test_tensorrt_model.cpp 配合现有模型与图片验证；该工具不启动主程序、采集或鼠标服务。

图片推理基准使用 tools/benchmark_tensorrt.cpp，通过 tools/build_performance.ps1 编译。必须用相同图片、模型和参数进行对照，并分别说明预处理、GPU 等待与后处理的测量范围。不要用单次最高速度代替持续性能。
