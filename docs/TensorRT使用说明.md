# N卡专用推理（TensorRT）

“N卡专用推理”是第三种推理引擎，使用 NVIDIA 显卡和 `.trt` 模型。NCNN、ONNX 入口继续保留，已有配置不自动切换。

## 模型与选择

| 网页选项 | 配置值 | 程序同目录的模型 |
|---|---:|---|
| NCNN | 1 | `<模型名>.param` 和 `<模型名>.bin` |
| ONNX | 2 | `<模型名>.onnx` |
| N卡专用推理 | 3 | `<模型名>.trt` |

例如网页“游戏模型”选择“三角洲行动”，N卡专用推理使用程序同目录的 `三角洲行动.trt`。也可使用自己的文件名：将 `新模型名.trt` 放到程序同目录，选择“N卡专用推理”后点击“刷新模型”，再从游戏模型列表选择“新模型名”。文件名与列表名称对应，列表不显示扩展名。

服务端配置沿用系统 ANSI / GBK 编码，模型名称请使用能在该编码中表示的常用中文、英文或数字；包含 emoji 等字符的名称需先改名。

## 转换步骤

1. 在准备运行的电脑上打开 `x64/Release/ONNX转TRT工具.exe`。
2. 选择原 `.onnx` 文件和输出 `.trt` 路径。工具固定生成 FP16，可直接选择普通 FP32 ONNX；转换只在内存中进行，原 ONNX 文件保留。
3. 开始转换并等待成功，转换可能比加载已有模型耗时长。
4. 将生成的 `.trt` 放到主程序同目录，打开网页选择“N卡专用推理”，点击“刷新模型”，选择生成的模型名称。

原程序同目录已有同名模型时，先确认是否需要替换；转换失败时不应当把未完成文件作为可用模型。

界面显示“推理精度：FP16”，没有 FP32 或 TF32 选项。命令行默认也是 FP16，无需额外精度参数；可显式传入 `--fp16`，含义相同。转换后验证引擎的输入和输出确为半精度，再保存完成文件。

```powershell
& './x64/Release/ONNX转TRT工具.exe' --input './x64/Release/三角洲行动.onnx' --output './x64/Release/三角洲行动.trt'
```

动态输入模型可用 `--size 宽x高` 指定尺寸；只有明确需要替换现有输出时使用 `--overwrite`。

TensorRT 模型与生成时的显卡和运行环境有关。换显卡、换电脑或升级相关运行库后，建议从原 ONNX 重新转换；加载失败时，可先切回 ONNX，并查看程序同目录的 `运行日志.txt`。

## 支持范围与依赖

当前接入使用 TensorRT 11.3.0.99、CUDA 13.4。N卡专用引擎按选择加载相关运行库；继续使用 NCNN 或 ONNX 时不要求 NVIDIA 显卡，也不需要启动该引擎。

从源码重建时，执行 `tools/install_tensorrt.ps1` 准备 TensorRT SDK，安装 CUDA 13.4 Toolkit，并设置 `CUDA_PATH` 或 `SagaCudaDir`；SDK 用于编译，运行库随构建复制。安装脚本不安装显卡驱动。运行 N卡专用引擎和转换工具仍需兼容的 NVIDIA 显卡及驱动。

当前支持 YOLOv8 / YOLOv11 的普通目标检测导出：单个 RGB 输入 `[1,3,H,W]`，尺寸不超过 4096，单个原始检测输出 `[1,4+类别数,候选框数]`。不是所有 ONNX 或 YOLO 导出都能使用；带内置 NMS、多输出、姿态、分割等模型不在本轮支持范围。权重需嵌入 ONNX；自定义算子、未内联函数和 Range 算子暂不支持，遇到这些模型会报告转换错误。推荐固定尺寸的标准目标检测导出。

模型名只用于选择同名文件，不会把其它格式自动转换成 `.trt`。FP16 会有舍入差异，需要在自己的模型与画面上比较。

## 实测结果与范围（2026-10-03）

本轮使用 RTX 4080 SUPER、NVIDIA 驱动 616.92；测试 GPU 以真实硬件标识确认。模型输入 416×416、9 类，将原 ONNX 自动转换为 FP16 后生成引擎。引擎优化生成约 87.40 秒，生成 21,450,748 字节的 `.trt` 文件。部署目录的 `三角洲行动.trt` 已替换为此 FP16 模型；原 ONNX 的 SHA256 保持不变。

转换中间模型通过 ONNX 完整类型检查，输入、输出和全部浮点权重为 HALF；1320441 个浮点权重与 NumPy 的 FP16 转换逐个一致，整数权重、维度和模型元数据保留。工具独立运行不需要 Python；上述 ONNX/NumPy 仅用于开发验证。

从 125,248 张图片中等距抽取同一批 2048 张，中心裁剪最大 320×320，预先读取解码，每轮重复 3 次；置信度 0.25、NMS 0.45、最多 99 框，OpenCV 2 线程。两次运行平均：

| 同批图片 | 平均预处理＋推理＋后处理 |
|---|---:|
| ONNX / DirectML（两轮重测） | 1.27746 ms |
| TensorRT FP16＋CUDA Graph＋阻塞同步（默认） | 0.67944 ms |

本组默认 TensorRT FP16 平均耗时低约 46.81%。两者均不包含读取、解码、选靶和鼠标操作，不能外推为采集卡帧率或完整操作延迟。FP16 两轮平均分别为 0.678673 / 0.680206 ms，ONNX 为 1.279276 / 1.275651 ms。

ONNX 共 6559 框，FP16 共 6560 框；7/2048 张图片的检测数量或类别数量有变化。按同类别、IoU ≥ 0.5 匹配，匹配 6556 框，ONNX 未匹配 3 框、FP16 未匹配 4 框。匹配框的最大坐标分量差 P95 为 1 像素、最大 13 像素；置信度绝对差平均约 0.000551、最大约 0.037225。这是输出差异比较，裁剪测试没有使用标签评估准确率或 mAP。

FP16 重复两轮的检测输出逐字节一致。GPU 集成测试中，CUDA Graph 与普通执行在同一测试图片及切换黑图再恢复时的原始输出也逐字节一致。

默认等待 GPU 时使用阻塞同步，减少 CPU 持续忙等。本轮 CPU 消耗约为 0.535 个核心。诊断时可在启动程序前设置 `SAGA_TRT_BLOCKING_SYNC=0` 切到忙等模式；移除该环境变量或设为 `1` 后重启恢复默认。

实机 NV12 1920×1080、240 FPS、320 中心裁剪，10 秒处理 2400/2400 帧。FP16 默认模式取帧返回至结果平均约 1.280 ms，中位数约 1.002 ms、P95 约 2.226 ms；当时画面没有目标，目标场景由图片集覆盖。该结果不包含采集卡内部、输入设备和鼠标输出的延迟。

模型文件及原始实验输出不入库。图片测试工具：

```powershell
./tools/build_performance.ps1 -Source tools/benchmark_tensorrt.cpp -Name benchmark_tensorrt
& './.workbuddy/performance/bin/benchmark_tensorrt.exe' './x64/Release/三角洲行动.trt' 'D:/三角洲行动圣人数据集/images' 320 2048 3 './.workbuddy/performance/trt-recheck' 1 2
```

CPU 回归检查使用 `tools/test_tensorrt.ps1`：模型目录发现、生产 HTTP 路由、未初始化引擎的参数防护以及 FP16 数值舍入、张量转换、Resize 必要参数转换和异常模型数据；不会启动主程序、驱动、鼠标或 GPU 推理。

主程序和转换工具的 Release / Debug 均编译通过。实际 GPU 集成测试已验证：直接 BGR、带行填充的 BGR、普通/倒向 BMP 结果一致；切换新图再恢复原图时输出一致；重复加载/销毁三次、99/100 结果缓冲边界、缺失/空/损坏模型的诊断与随后加载有效模型恢复均通过。原 `.trt` 文件保持只读，实际加载的 TensorRT / CUDA DLL 位于程序同目录。

这组测试覆盖本轮固定 SDK 和上述模型；不代表任意模型、显卡或其它 SDK 版本均已验证。需要重跑实际模型测试时，先等待 GPU 空闲；下列工具会使用 GPU，但不启动主程序、驱动安装或鼠标服务：

```powershell
./tools/build_performance.ps1 -Source tools/test_tensorrt_model.cpp -Name test_tensorrt_model
# 放到已有运行库的部署目录，核对从程序同目录加载 DLL。
Copy-Item './.workbuddy/performance/bin/test_tensorrt_model.exe' './x64/Release/test_tensorrt_model.exe'
& './x64/Release/test_tensorrt_model.exe' './x64/Release/三角洲行动.trt' 'D:/你的测试图片.jpg' --expect-fp16
```

图片需可正常解码；使用自己已有的测试图片替换路径。模型和图片不会被覆盖，异常模型样本在测试自己的临时目录创建并清理。
