# TensorRT 持续运行延迟诊断与修复

2026-10-03，在本机 RTX 4080 Laptop GPU、NVIDIA 616.92 WDDM 驱动、TensorRT 11.3 / CUDA 13.4 上实测。使用 `D:\圣人自用\模型数据\三角洲416.trt` 原有引擎，没有重新转换或替换实际目录中的模型。采集设备为 Live Gamer Ultra 2.1，1920×1080@240 NV12，中心裁剪 416×416。

## 结论

复现了持续运行后由约 1ms 上升到约 2.4ms 的现象。主要原因是 GPU 在轻负载下自动进入 P5：核心由 2280MHz 降到约 1095–1215MHz，显存由 9301MHz 降到 810MHz。温度约 39℃，当时 `nvidia-smi -q` 的 idle 原因为 Active，热限制、功率限制均为 Not Active，不是散热不足导致的降频。

默认 CUDA 阻塞事件同步另外增加了 CPU 唤醒等待。只将其关闭仍然约 2.27ms，不能解决 GPU 降频。CUDA Graph 在变慢时仍为 active，没有发现图重放失效或切回 ONNX 的证据。

同一段运行中临时将核心锁到 2100MHz、显存锁到 9001MHz后，总耗时立即回到约 1.25ms，GPU 计时回到约 0.76ms。实验结束已执行 `nvidia-smi -rgc`、`nvidia-smi -rmc`，没有留下全局锁频。

## 修复与实测

单独设置 NVIDIA 程序配置“优先最高性能”对这个纯 CUDA 测试进程未生效。建立同显卡的 D3D11 设备后，程序配置生效，GPU 保持 P0。源码现通过 CUDA 设备 LUID 匹配 DXGI 适配器，仅持有 D3D11 设备，不提交绘图、不创建交换链，也不在后台空跑推理。

同时默认改为 CUDA 事件的非阻塞同步；仍然在读取输出前等待 GPU 完成。需要降低 CPU 使用时，可设置 `SAGA_TRT_BLOCKING_SYNC=1` 恢复阻塞方式。界面耗时改为三位小数。

| 真实采集测试 | 总运行时长 | 30秒之后的平均耗时 | GPU事件区间平均耗时 |
|---|---:|---:|---:|
| 原阻塞同步，纯 CUDA | 150秒 | 2.444ms | 1.571ms |
| 仅关闭阻塞，纯 CUDA | 90秒 | 2.266ms | 1.554ms |
| D3D 程序配置实验 | 90秒 | 0.975ms | 0.706ms |
| 最终修复源码，默认事件同步 | 120秒 | 1.006ms | 0.748ms |
| ONNX / DirectML | 90秒 | 1.764ms | 未采集 |

平均值按每秒窗口内的帧数加权。各组真实采集画面随时间变化，因此不能当成完全相同图片的模型性能排名。所有引擎均处理约240采集帧/秒。GPU事件区间包含上传、推理、下载和区间内可能的调度时间，**不是仅神经网络内核耗时**。总耗时包含预处理、提交、同步及后处理，不能保证每一帧低于1ms。

编译后的实际主程序另运行采集与推理：40次每秒HTTP采样，平均1.011ms，范围0.839–1.236ms，处理帧率240FPS。程序每5秒诊断摘要也显示CUDA Graph生效、非阻塞事件同步和持续约1ms的耗时。主窗口、串口COM3连接、网页监听与模型加载正常；窗口截图接口超时，因此未验证截图视觉布局。

相同的真实采集图片上，阻塞事件、非阻塞事件及关闭CUDA Graph三组均检测到15个目标；图重放开始后的类别、置信度、坐标导出文件完全一致（SHA256均为 `B96EEC431A65BFEDD2FD8EEBC9A2D9AE7D53B93D591F7383FCAA1F8420C5DA58`）。这验证同步修改未造成输出读取不完整；不是全面的精度评测。

转换工具也成功将原ONNX生成到 `diagnostics/converted-validation.trt`，该测试引擎成功加载并推理；不存在的输入正确返回失败。测试引擎不会替换实际目录的原引擎。

## 构建与文件位置

用于测试的本地源码副本缺少 `Dependencies.props`、`RuntimeDependencies.targets`、`TrtConverter.vcxproj`、`tools/build.ps1`，原样MSBuild报缺失工程/导入文件，测试时先补齐。发布到GitHub时保留仓库原有完整构建工程、依赖验证和许可证复制规则，只增加CUDA API头文件与独立运行时目录支持；主程序与转换工具Release x64编译通过。

CUDA Toolkit未安装。为动态调用运行时API，下载官方CUDA 13.0的cudart / CRT头文件包并校验SHA256；运行时仍用实际目录已有的CUDA 13.4 DLL。复现头文件准备：

```powershell
./tools/prepare_cuda_headers.ps1
./tools/build.ps1
```

下载走用户指定的 `http://127.0.0.1:7897`。其余SDK沿用项目已有`.deps`。CUDA头文件不替代运行库；只有已有兼容的CUDA 13.4 DLL时，才可将它们放到`.deps/cuda-runtime-13.4`，或通过`SagaCudaRuntimeDir`指定现有目录。完整Toolkit构建方式仍然支持。

可选程序性能配置工具的重建方法：

```powershell
./tools/prepare_nvapi.ps1
msbuild NvPowerProfile.vcxproj /p:Configuration=Release /p:Platform=x64
./x64/Release/NvPowerProfile.exe query 圣人双机服务端.exe
./x64/Release/NvPowerProfile.exe set 圣人双机服务端.exe diagnostics/nvidia-settings-before.nip
```

工具仅创建自己的专用程序配置，遇到该EXE已有其它配置时会拒绝修改。设置前备份驱动配置；修改后重启软件。NVAPI头文件按固定官方提交下载并逐文件校验，SDK不随源码上传。

修复版程序：`D:\C++采集卡源码\x64\Release\圣人双机服务端.exe`。当前运行的是这个程序，测试配置关闭了自瞄/扳机热键，以便只测试采集和识别。实际目录 `D:\圣人自用` 的EXE、模型、用户配置未覆盖；实际目录原EXE的SHA256仍为 `B8E396EB6F9AC86C299BE30EE29ABCD8FCB985EE26952F2F66175F334801C682`。

如需在实际目录使用修复，将原EXE先保留一份，再复制上述新EXE到实际目录；原模型和配置继续使用。仅旧EXE配合程序性能配置不能解决本机问题，需要新版的D3D设备处理。不要将源码输出的测试配置覆盖到实际目录。

## NVIDIA 配置与撤销

通过官方NVAPI新建了两个专用应用配置，仅匹配 `圣人双机服务端.exe`、`InferenceBench.exe`，电源管理模式为1（优先最高性能）。设置前它们都没有独立配置；没有修改全局电源管理模式。原驱动设置完整备份为 `diagnostics/nvidia-settings-before.nip`。Windows电源方案仍是原来的“平衡”。

按程序性能策略使GPU工作时功耗约37W，原节能状态约20W。非阻塞同步会增加CPU活动，这是换取更稳定低延迟的代价。关闭TensorRT引擎会释放D3D设备；没有额外常驻保频进程。

需要撤销本次添加的程序配置时，先退出程序，再运行：

```powershell
./tools/restore_nvidia_profile.ps1
```

该脚本仅删除本次创建的两个专用配置，不用完整备份覆盖其他后续设置。`SAGA_TRT_POWER_PROFILE=0` 可单独关闭源码中的D3D设备处理；不需要NVIDIA策略的机器可用它对照。

## 诊断工具

`InferenceBench.vcxproj`生成`x64/Release/InferenceBench.exe`，直接调用项目中的推理与采集代码，不连接串口、不执行鼠标动作。

```powershell
$env:SAGA_TRT_PROFILE='1'
./x64/Release/InferenceBench.exe trt 'D:\圣人自用\模型数据\三角洲416.trt' 120 240 diagnostics/retest.csv capture
```

诊断环境变量默认关闭；只有`SAGA_TRT_PROFILE=1`时才插入GPU计时事件并在主程序每5秒写一条性能摘要。普通使用没有逐帧性能日志。CSV、输出对照、GPU每秒监控、构建日志均保存在项目`diagnostics`及根目录的`build-*.log`中。

NVIDIA官方也说明浮动频率会影响TensorRT计时，Windows WDDM与阻塞同步可能带来额外延迟和波动，参见 [TensorRT性能测量指南](https://docs.nvidia.com/deeplearning/tensorrt/latest/performance/benchmarking.html)。本机D3D设备与程序电源配置的组合效果来自上述实测，不作为所有机器都有效的保证。设备匹配使用[CUDA公开LUID查询](https://docs.nvidia.com/cuda/cuda-driver-api/cuda_driver_api/group__CUDA__DEVICE.html)；程序设置来自[NVIDIA官方NVAPI定义](https://github.com/NVIDIA/nvapi/blob/main/NvApiDriverSettings.h)。
