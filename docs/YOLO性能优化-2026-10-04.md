# YOLO 热路径优化与实测（2026-10-04）

## 结论

当前项目的主要可落地收益在 TensorRT 的预处理和候选评分。已经保留原模型、置信度阈值、NMS、99 目标上限和默认同步方式，完成代码修改与图片对照。

| 416 中心裁剪，TensorRT 默认同步 | 修改前 | 修改后 |
|---|---:|---:|
| 平均完整识别耗时 | 0.611835 ms | 0.564423 ms |
| P50 | 0.5676 ms | 0.5216 ms |
| P95 | 0.6884 ms | 0.6336 ms |
| FP32 中间张量占用 | 2,076,672 字节 | 0 |

平均耗时减少 **7.75%**，对应图片推理吞吐提高约 **8.40%**。内存减少约 **1.98 MiB**，指删除的 CPU 中间张量，不能当作整个进程内存或显存减少比例。模型 GPU 运算量、模型大小未改变。满速非阻塞同步仍消耗约一个逻辑核心；同样数量图片的 CPU 时间随总耗时下降，不等于满速运行的 CPU 百分比同比下降。

## 改了什么

1. `TensorPixels.h` / `preprocessing.hpp`：原有 BGR→RGB 平面归一化支持直接输出 FP32 或 FP16。FP16 在寄存器中完成原来的 FP32 乘法和就近舍入，直接写入页锁定输入，避免“写完整 FP32 张量、再读一遍转换”的内存流量。FP32 输入也免去整块复制。
2. `TensorRT.cpp`：使用上述外部输出缓冲，不再分配浮点输入中间张量。输出半精度解码路径、GPU 拷贝、CUDA Graph 和同步顺序保持不变。
3. `YoloScores.h`：每批 8 个候选并行比较类别评分，只读取通过阈值的候选坐标。保持候选顺序、同分首类别和非有限胜出评分过滤；坐标还原与 NMS 沿用原实现。
4. 填充缓存同时检查输出地址、元素大小、内容尺寸和通道数，防止更换缓冲区或格式时复用错误灰边。
5. `benchmark_tensorrt.cpp`：修复阻塞标志的报告，增加输入字节数和中间张量容量。旧工具只要完成事件存在就打印 `blocking_sync=1`，不能用这条旧日志判断真实模式；本次基线默认组实际未设置阻塞环境变量。

ONNX 已有固定输入/输出复用、DirectML 单线程与关闭闲置线程自旋，NCNN 已有融合预处理与向量后处理。这次未改它们的模型、推理选项及 NMS；共享的浮点像素路径进行了回归验证。

## 实测方法与边界

- 基线源码：`17a89a0ce4dffec1ccfe801acff2fee3497a2190` 中的推理代码，工作区已有网页和文档修改不属于本次优化。修改前已编译保存独立基线程序。
- 本机 `nvidia-smi` 与 NCNN Vulkan 报告 RTX 4080 SUPER，驱动 616.92；DXGI 名称显示 GTX 750，名称来源不一致。所有前后组使用同一机器、同一模型及同一设备选择。不能沿用 10 月 3 日笔记本报告的绝对时延。
- 模型：`x64/Release/模型数据/三角洲416.trt`，SHA256 `ACFDF5906974B80654B6F92ACDA3F3785C3ACDEECE89E6DE83619E70F3B9843A`。输入 FP16 416×416，9 类、3549 个候选；未重新转换引擎。
- 图片：`D:\三角洲行动圣人数据集\images`，共发现 125,291 张支持格式图片，按排序均匀抽取 2048 张。并非测试全部图片。
- 相同编译选项 `/O2 /Ob3 /arch:AVX2 /fp:fast`、OpenCV 单线程、CUDA Graph 开启，置信度 0.25、NMS IoU 0.45、最多 99 个结果。
- 每进程预热 50 次，图片预先解码入内存。按“旧→新→新→旧”运行，每组 2048 张×5 轮，前后各 20,480 次计时。表中统计合并两次相同版本的全部 CSV 记录，P95 不是两次 P95 的平均。
- 耗时覆盖生产 BGR 推理接口，包括预处理、GPU 提交/执行/同步和后处理；不含磁盘读图、JPEG 解码、采集等待、预览、选靶和鼠标输出。未宣称采集整机 FPS 同比提高。
- 每进程只导出首轮检测结果。2048 张的 416 裁剪结果，框、类别、顺序、置信度逐字节一致；SHA256 `B5DD793EBBDD84B4EB2D5C01F44EE178567398C27DC47289240087AC85C1EBEF`。
- 另对同批 2048 张各做原图、320 中心裁剪前后对照，结果均逐字节一致。原图单轮平均 0.692→0.642 ms；320 裁剪单轮平均 0.693→0.666 ms，但 P95 从 0.835 升至 0.894 ms。后两组主要用于输出回归，单轮结果不证明所有场景的尾延迟都下降。
- ONNX、NCNN 分别使用各自原模型，512 张原图前后检测文件完全相同。不能把不同后端之间的精度差异归因于本次优化，也不宣称 ONNX、NCNN 获得上述提速。
- ONNX 该单轮平均为 1.272→1.283 ms。NCNN 首轮出现较大尾延迟波动，因此追加“新→旧→旧→新”、每组 512 张×5 轮复测：旧版两组平均 1.723 ms，新版两组平均 1.755 ms（约 +1.9%）。这些数据没有显示其性能收益；本次对两者的承诺是输出兼容，不将短时波动包装成加速。

这是输出一致性验证，不是对标注计算 mAP 的精度评测，也不能证明所有其他模型和显卡都同样提速。

## 降低 CPU 活动的现有选项

相同 2048 张、5 轮图片测试，优化后的 TensorRT：

| 同步方式 | 平均耗时 | CPU 时间 / 墙钟时间 |
|---|---:|---:|
| 默认，短时自旋等待 | 约 0.564 ms | 约 1.00 个逻辑核心 |
| `SAGA_TRT_BLOCKING_SYNC=1` | 0.582 ms | 0.172 个逻辑核心 |

阻塞组相对默认平均耗时增加约 0.018 ms，测试批次 CPU 核心等效占用降低约 83%，检测结果完全相同。此处 CPU 统计包括推理及基准循环/CSV 写入，排除模型加载和图片读取；不是任务管理器整机 CPU 百分比。旧实现阻塞组为 0.626 ms、0.288 个逻辑核心，新实现也减少了该模式的 CPU 工作量。

由于此前笔记本上阻塞唤醒影响更大，本次没有覆盖原来的低延迟默认值。需要低 CPU 时，可以在 PowerShell 中启动：

```powershell
$env:SAGA_TRT_BLOCKING_SYNC='1'
& 'D:\C++采集卡源码\x64\Release\圣人双机服务端.exe'
```

环境变量在引擎创建时读取，需要重启程序或重新加载引擎。它只影响从该 PowerShell 启动的进程。恢复默认：退出程序，在同一窗口执行 `Remove-Item Env:SAGA_TRT_BLOCKING_SYNC` 后重新启动。直接从未设置此变量的桌面环境启动仍是默认模式。

未改全局电源策略、GPU 锁频或用户模型；也没有用跳帧、降低输入分辨率、提高阈值或减少目标上限换取数字上的提速。

## 验证与复现

CPU 回归 `tools/test_yolo_hotpath.cpp`：225 组候选评分对照（含 NaN/Inf、同分、阈值边界、尾部及 4096 类）；120 组 FP32/FP16 布局逐位对照（原图、缩放、动态尺寸、灰边、非连续 ROI、交替目标地址和输出保护），另外遍历全部 256 种像素值与 1～33 宽度的 SIMD 尾部。

已有验证：56 组浮点像素布局、32 组 letterbox 几何、TensorRT 无 GPU 参数防护，以及真实 GPU 的 BGR/行填充/BMP、99 结果边界、CUDA Graph 新输入、重复加载和错误恢复。主程序和转换工具 Release x64 构建通过。

## 后续优化的优先级

- 优先按实际采集帧率验证阻塞模式：这是目前降低 CPU 活动最明显、且不改识别结果的选择，但必须观察目标机器的唤醒延迟。
- GPU 预处理、GPU NMS 可以作为后续实验；当前输入小、候选通过阈值后较少，额外内核提交和数据转换未必划算，未在本次盲目替换。
- 更小输入、INT8、改变模型结构属于准确率与性能之间的取舍，需要单独用标注集评估，不能用本次“检测输出一致”的结论替代。
