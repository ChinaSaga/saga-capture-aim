# 依赖更新与验证（2026-10-02）

本次更新项目实际使用的 C++ 库、随程序部署的运行库及源码分支。以官方稳定版为准，SDK 安装在项目 `.deps` 下；原 D 盘 SDK 保留。下载哈希、源码提交见 `dependencies.lock.json`，构建与性能工具共同读取 `Dependencies.props`。

官方 `Microsoft.ML.OnnxRuntime.DirectML` 包目前仍是 [1.24.4](https://www.nuget.org/packages/Microsoft.ML.OnnxRuntime.DirectML)。直接换成官方普通 1.30 DLL 会丢失 DirectML，所以本次从最新官方源码启用 DirectML 编译。保留 CPU 和 DirectML 两种执行提供程序。

YOLOs-CPP、MAKCU 属于已深度修改的源码分支，本次没有整包覆盖成上游 SDK。YOLO 的最新适用坐标修正已合并；MAKCU 的上游新增 C++23 接口、回调与运动命令不是当前程序使用的接口。本地二进制按键报文兼容和运动格式化优化继续保留。

网页只使用本地 JavaScript/CSS，没有外部前端包。原生采集、推理和人手训练不依赖 Python；目录中的旧 Python 训练参考脚本属于独立工具环境，本次不修改全局 Python、显卡驱动、WCH 驱动或 Windows 系统组件。

性能和模型转换工具的可选依赖也核对为 PyPI 当前稳定版：NumPy 2.5.3、ONNX 1.23.1、onnxconverter-common 1.16.0、Pillow 12.3.0，固定在 `tools/requirements-performance.txt`。本机测试使用隔离的 `.workbuddy/performance/python`，没有替换系统 Python 包。

## 兼容改动

- OpenCV 5 的旋转框几何接口移动到 `opencv2/geometry.hpp`，已按主版本条件引入；运行检查自动匹配头文件版本对应的 DLL。
- Asio 移除 `address::from_string`，Cat 改用同语义的 `ip::make_address`。
- YOLO 使用与 Python 一致的偶数舍入，并用实际整数填充恢复坐标，修正非正方形图片、奇数填充时的偏移。常用 320×320 中心裁剪路径不受该坐标修正影响。
- ONNX Runtime 源码构建关闭预编译头与 VS 结构化诊断，避免当前中文工程路径引起的编码错误；没有修改上游运行库源码。
- 所有 DLL 和 OpenCV、NCNN、ORT、DirectML 许可证随构建自动部署，旧运行文件已备份到 `.workbuddy/dependencies-backup/release-before-library-update`。
- 按用户要求移除 `onnxruntime_providers_shared.dll`：当前 CPU / DirectML 均编入 `onnxruntime.dll`，部署和性能工具只复制主运行库，后续构建也清理旧目录中的该桥接 DLL。
  已验证移除后 DirectML 128 张图片、CPU 32 张图片推理正常；隔离部署测试确认旧 DLL 会被清理且不会重新复制。

## 验证

最终应用 **Release、Debug 均编译通过**，运行文件实际依赖 `opencv_world500.dll`、ONNX Runtime 1.30.0 和最新 NCNN。原模型与 FP16 模型哈希没有变化。ONNX Runtime 1.30 的原生 API 验证确认 API 30，并包含 `DmlExecutionProvider` 和 `CPUExecutionProvider`；CPU 回退也通过 32 张图片推理。

已通过 56 组像素预处理精确对照、32 组 letterbox 几何和坐标往返、7,680 组采集转换精确对照及截断帧检查、MAKCU 协议回归。测试可执行文件与详细结果保存在 `.workbuddy/dependency-updates/validation`。

从 124,805 张图片中均匀抽取同一批 **2048 张**，中心裁剪最大 320×320、模型输入 416×416；置信度 0.25、NMS 0.45、最多 99 框，OpenCV 16 线程。每种库版本各跑两次、每次 3 轮，正式计时前热身 50 张，读取/解码不计入下表；先旧后新、再新后旧。以下是两次运行均值，未据此归因到某一个库。

| 推理路径 | 旧依赖平均耗时 | 新依赖平均耗时 | 变化 |
|---|---:|---:|---:|
| ONNX 原模型 | 1.18868 ms | **1.18758 ms** | −0.09%，基本不变 |
| ONNX FP16 | 1.06942 ms | **1.07638 ms** | +0.65% |
| NCNN | 1.73236 ms | **1.77499 ms** | +2.46%；新版单次运行范围 1.747～1.803 ms |

升级不等于提速；本次 NCNN 均值略慢，原 NCNN DLL/LIB 实际未改变，同时更新了 OpenCV 和相关源码。按用户更新库的要求保留最新版本，所有单次运行数字保存在原始 CSV 中。

各路径的首轮 2048 张完整输出（框、类别、置信度）在四次运行间 **逐字节一致**：原 ONNX 6,488 框、FP16 6,487 框、NCNN 6,477 框。这里比较的是每条路径升级前后，FP16 与原模型之间的精度差异仍见原性能报告。三轮均计时，只导出首轮框结果供精确对照。

真实 NV12 1920×1080、240 FPS 采集卡、320 中心裁剪，原模型和 FP16 分别跑 10 秒：均处理 **2400/2400 帧**、无未处理帧，约 **239.99 FPS**。拿到帧至结果的平均耗时分别为 1.748 / 1.631 ms；实测画面没有目标，目标场景用图片集覆盖。该计时不是从采集卡输入到鼠标动作的完整延迟。

详细记录：`.workbuddy/dependency-updates/results/summary.json`、各路径 `.csv`、`.detections.bin` 和采集日志；原模型精确对照为 `compare-fp32.json`。依赖安装脚本本机检查通过；ONNX 源码构建脚本已经完整执行成功。

## 重建与回退

```powershell
./tools/install_dependencies.ps1 -Python 'C:/你的Python/python.exe'
./tools/build.ps1
```

首次源码构建 ONNX Runtime 需要 Git、Python 和 Visual Studio 18 C++ 工具；脚本按固定提交及 DirectML 包哈希构建。已安装本次 SDK 的本机可直接执行 `tools/build.ps1`，不必再次编译运行库。

原运行文件和旧基准程序分别保存在 `.workbuddy/dependencies-backup/release-before-library-update`、`benchmark-before-library-update`。原模型和 FP16 模型继续使用，未重新导出权重。
