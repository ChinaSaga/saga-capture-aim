# 采集与 YOLO 性能实测（2026-10-02）

本文记录库升级前的性能优化实验；随后完成的最新库迁移与对照结果见 [依赖更新记录](依赖更新-2026-10-02.md)。

原采集链路已经接近采集卡的 240 FPS 上限。此次保留 DirectML 工作线程精简、采集异常帧检查，并生成可选 FP16 模型；不采用实测变慢或读取旧图片的方案。

## 测试条件

- 基线源码：Git `76cdb1f`，通过源码快照独立编译，与修改版使用相同编译开关。
- CPU：Ryzen 9 9950X3D；GPU：`nvidia-smi` 报告 RTX 4080 SUPER。DXGI 的显示名称被改为 GTX 750，但 PCI ID 为 `0x2702`、专用显存约 16 GiB；DirectML 使用索引 0。
- OpenCV 4.12，ONNX Runtime 1.24.4，DirectML 1.15.4，x64 Release、AVX2、`/O2 /Ob3 /fp:fast`。主程序另外启用 LTCG。
- 模型：`x64/Release/三角洲行动.onnx`，输入 `[1,3,416,416]`，输出 `[1,13,3549]`，9 类。
- 图片目录：`D:\三角洲行动圣人数据集\images`，共 124805 张。按文件名排序并等距抽样，提前读取和解码。
- 主要对照：2048 张、中心裁剪最多 320×320、预热 50 次、重复 3 轮。置信度 0.25、NMS IoU 0.45、最多 99 个目标，OpenCV 默认 16 线程。
- 图片计时覆盖预处理、同步推理及后处理；不含文件读取、解码、选靶、鼠标轨迹或界面绘制。CSV、抽样清单、检测二进制和实验记录保存在 `.workbuddy/performance/`。

## 原模型与可选 FP16

| 2048 张图片测试 | 平均识别耗时 | 中位数 | P95 | 连续识别能力 |
|---|---:|---:|---:|---:|
| 原版代码＋原 FP32 模型 | 1.19924 ms | 1.17930 ms | 1.38240 ms | 833.86 次/秒 |
| 修改代码＋原 FP32 模型 | 1.19904 ms | 1.17840 ms | 1.38450 ms | 834.00 次/秒 |
| 修改代码＋可选 FP16 模型 | 1.08201 ms | 1.06330 ms | 1.26960 ms | 924.21 次/秒 |

代码线程调整没有明显提高识别速度；FP16 的平均耗时降低约 9.8%，连续识别能力提高约 10.8%。这些数值不是摄像头 FPS。

修改代码继续使用原模型时，2048 张图片的 6488 个检测结果逐值完全一致，包括坐标、类别和浮点置信度。

FP16 是有精度差异的可选模型。2048 张中心裁剪图片中，7 张的检测数量或类别数量变化；原模型得到 6488 个目标，FP16 得到 6487 个。按同类框 IoU≥0.5 配对，95% 的框分量变化不超过 1 像素，最大 4 像素；匹配目标最大置信度差约 0.037。

另用 512 张未裁剪整图及现有标签评估：

| 置信度 0.25、IoU 0.5 | TP | FP | FN | 精确率 | 召回率 |
|---|---:|---:|---:|---:|---:|
| FP32 | 1422 | 239 | 176 | 85.61% | 88.99% |
| FP16 | 1423 | 239 | 175 | 85.62% | 89.05% |

以上是固定阈值的抽样结果，依赖现有标签，不能解释为完整数据集 mAP 或所有场景精度相同。

原模型未覆盖，SHA256：`2B0CAE805A10FD8DA3050955158F01F58185092B19283EBE2D786B4B22A52BF1`。
可选模型：`x64/Release/三角洲行动_FP16.onnx`，约 2.71 MB，保留 FP32 输入输出和模型元数据；SHA256：`E017D3F54D1179E99DE2EE64EEC899FD33AB642B786CD9B4531874C889EF25B7`。

使用时将推理引擎设为 ONNX，在网页“游戏模型”选择“三角洲行动（FP16加速，ONNX）”。原模型仍是原名称，配置未自动切换。NCNN 引擎不能直接加载此 ONNX 文件。

## 采集实机

设备为 Live Gamer Ultra 2.1-Video，NV12、1920×1080、240 FPS、320 中心裁剪。

- 纯采集：8.004 秒收到 1918 个独立帧，239.629 FPS，没有序号遗漏。
- 采集＋原 ONNX：10 秒完成 2400 帧，约 239.99 FPS，2400 个已发布帧均处理。
- 修改版＋原 ONNX及 FP16 各完成 2400/2400 帧，均接近 240 FPS。
- 在同一组实机对照中，取到帧后至识别输出平均约为 1.775 ms（基线）、1.818 ms（修改版原模型）、1.702 ms（FP16）；对应 P95 约 2.170/2.161/2.130 ms。空闲间隔下的 GPU 调度、时钟及系统负载会影响耗时。
- 当时采集画面没有检出目标；检测结果丰富的场景由真实图片基准覆盖。

实机延迟从 `captureAcquire` 返回开始计算，不包含输入设备、采集卡内部、驱动缓冲或鼠标输出延迟。整条“采集→选靶→鼠标”链路仍未在本轮测量。

## 保留的代码修改

1. `src/session_base.hpp`：DirectML 默认 1 个 CPU 推理线程，关闭线程自旋；CPU/CUDA 默认线程策略和显式线程数保持原逻辑。ABBA＋BAAB 共 32000 次对照中，6 线程与 1 线程平均为 1.11759/1.11439 ms，耗时基本相同，确定减少 5 个闲置工作线程。CPU 时间汇总减少 8.2%，但分组波动明显，不承诺固定 CPU 降幅。其他模型若有较多算子落在 CPU，需重新测试线程配置。
2. `src/OpnecvCapture.cpp`：回调入口丢弃空指针、负长度、截断样本和未配置状态，避免 SIMD 读取不完整帧或发布伪新帧。这是稳定性检查，没有宣称速度收益。
3. 网页加入可选 FP16 模型入口；源码及本机部署 HTML 均已更新。

## 已尝试并排除

| 尝试 | 结果 |
|---|---|
| 改写 NV12 SIMD 写入 | 约慢 3–5%；原 320 裁剪转换约 0.020 ms，撤回 |
| BGR 转平面减少读取次数 | 640×640 略慢，撤回 |
| CPU 输入只绑定一次的 IoBinding | 固定输入表面更快，但换图后 GPU 仍读旧输入；变化测试最大输出差 242.365，排除 |
| 每张图重新绑定输入 | 正确，但耗时与已有预分配输出 Run 基本相同 |
| DML 图优化级别调整 | 没有可靠加速，部分选项改变浮点输出，保留原级别 |
| GPU 常驻缓冲＋图捕获 | 包括真实上传、同步和读回的 1000 次配对测试：普通 Run 1.340–1.343 ms，常驻缓冲 1.405 ms，图捕获 1.365 ms，排除 |
| 仅检测头保留 FP32 的混合精度 | 约 7% 吞吐收益，但仍有同样数量的检测变化，未列为推荐模型 |
| OpenCV 单线程 | 320→416 的预处理从约 0.073 ms 升到 0.138 ms，保留默认并行策略 |

CPU 输入的设备复制发生在绑定时；修改同一 CPU 缓冲后必须重新绑定，不能仅依赖同步。依据：[ORT 官方 IoBinding 说明](https://onnxruntime.ai/docs/api/csharp/api/Microsoft.ML.OnnxRuntime.OrtIoBinding.html)。

## NCNN 对照

也测试了现有 `三角洲行动.param/.bin`，输入同为 416×416，输出 3549×13、9 类。512 张未裁剪图片、4 轮：首次 NCNN 平均 1.936 ms，进一步充分热缓存后的原路径为 1.777 ms；均慢于本机 ONNX 的约 1.20 ms，因此没有把现有 NCNN 设置作为加速方案修改。

- 显式跨帧复用 Vulkan blob/staging 分配器为 1.781 ms，与热缓存原路径基本相同，512 张检测二进制完全一致。默认实现本来就从池里取得和归还分配器，因此没有明显减少实际分配。
- 关闭 cooperative matrix 为 2.203 ms，较热缓存原路径慢约 24%，检测结果改变。
- 关闭 FP16 arithmetic 为 1.927 ms，没有明显收益，检测结果改变。

NCNN 生产源码未修改。ONNX 与 NCNN 后处理坐标语义不同，NCNN 工具把浮点框四舍五入后保存到对照文件；引擎间的框差异不能解释为代码优化导致的误差。现有 NCNN 与 ONNX 抽样检测数量也有差异，未假定两个导出文件逐值等价。

## 可复现工具与验证

`tools/build_performance.ps1` 使用本项目已有的 MSVC/SDK/库路径，并将测试 DLL 放在测试 EXE 旁，避免其他目录的同名 DLL 干扰。输出位于忽略目录 `.workbuddy/performance/bin`。

```powershell
cd D:\C++采集卡源码
& tools/build_performance.ps1 -Source tools/test_tensor_pixels.cpp -Name test_tensor_pixels
& .workbuddy/performance/bin/test_tensor_pixels.exe
& tools/build_performance.ps1 -Source tools/test_capture_pipeline.cpp -Name test_capture_pipeline
& .workbuddy/performance/bin/test_capture_pipeline.exe --validate

& tools/build_performance.ps1 -Name benchmark_onnx
& .workbuddy/performance/bin/benchmark_onnx.exe `
    'D:\C++采集卡源码\x64\Release\三角洲行动.onnx' `
    'D:\三角洲行动圣人数据集\images' 320 2048 3 `
    '.workbuddy/performance/recheck' 1

# 实机测试只打开采集卡并推理；先关闭正在使用采集卡的主程序。
& tools/build_performance.ps1 -Source tools/benchmark_capture_onnx.cpp -Name benchmark_capture_onnx
& .workbuddy/performance/bin/benchmark_capture_onnx.exe `
    'D:\C++采集卡源码\x64\Release\三角洲行动.onnx' 10 320 1
```

`tools/compare_onnx_detections.py` 比较相同抽样清单的框、类别和置信度；只有未裁剪整图可使用 `--labels ... --full-image` 计算标注指标。

`tools/convert_onnx_fp16.py` 可重新生成可选模型，支持 `--dependency-dir` 指定隔离安装的 `onnx`、`onnxconverter-common` 包；拒绝覆盖输入。转换器会清理导致 Resize 类型错误的内部注释，并严格检查公开输入输出和 ONNX 模型。当前依赖安装在 `.workbuddy/performance/python`，没有改动全局 Python 环境。

`tools/benchmark_ort_options.cpp` 为配置实验探针，包含刻意演示旧输入错误的 mode=2；它不是生产推理路径。GPU 常驻缓冲实验源码和记录保存在 `.workbuddy/performance/ort-options/`。

`tools/benchmark_ncnn.cpp` 使用实际 NCNN BGR 接口计时，与图片工具采用同样的抽样和阈值；未拆分的阶段时间在 CSV 中标为 NaN，只使用 total 进行速度对照。构建使用 `tools/build_performance.ps1 -Source tools/benchmark_ncnn.cpp -Name benchmark_ncnn`，第一个运行参数为 `.param`，同名 `.bin` 自动匹配，其余参数与 ONNX 图片工具一致。
