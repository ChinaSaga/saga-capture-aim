# 日志与性能

程序将运行诊断合并为 EXE 同目录的 `运行日志.txt`，采用 UTF-8 编码，方便直接查看或提供排错资料。

## 记录内容

- 启动步骤和耗时。
- Makcu 驱动检查、修复与连接诊断。
- 串口故障、协议异常及故障附近少量字节。
- 网络监听、端口回退、防火墙预检和网络状态变化。
- 模型加载与人手模型热加载结果。

正常推理、鼠标移动和正常按键不逐帧写日志。串口故障才记录必要的错误信息；网络报告仅在内容变化时进入日志。“本机网络检查”仍从内存中显示完整的最新报告。

## 写入与容量

业务线程将低频诊断放入内存队列，由后台线程以约 250 毫秒的窗口批量写盘；实际落盘时间还受线程调度和磁盘速度影响。推理和鼠标线程不等待磁盘写入。日志记录和清理仍有少量后台开销，不应将其理解为完全没有成本。

记录超过 2000 行时清理旧内容，保留最近 1000 行；文件同时受 1 MiB 上限约束。较大的单条记录和已有日志也按行数与字节数共同限制，因此实际保留行数可能少于 1000 行。日志文件不无限增长。

队列最多容纳 1024 条记录或 256 KiB，达到任一上限时丢弃较旧的待写记录，并在后续批次记录丢弃数量。单条文本限制为约 32 KiB，过大内容截断。文件被占用、锁不可取得或写入失败时，当前诊断批次可能丢失，业务线程不等待文件恢复。

异步队列尚未写入的最后几条记录，在强制结束进程或系统突然断电时可能丢失。独立验证工具可调用 `runtime_log::shutdown()` 排空队列；主程序强制结束进程时不保证最后一批诊断落盘。

## 旧版文件

新版不再生成 `SagaApp_startup.log`、`Makcu串口日志.txt`、`Makcu驱动报告.txt` 和 `网络自检.txt`。已有旧文件不会自动删除；确认无需保留后可手动删除。`人手数据.txt` 是采集数据，训练窗口中的输出是训练进度，都不属于本次合并的运行日志。

排错时提供 `运行日志.txt` 即可。
