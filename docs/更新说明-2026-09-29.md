# 2026-09-29 更新说明

本次更新将人手轨迹采集、CPU 训练和局域网网页调参整合到 Windows 主程序，并改善启动与网络故障处理。

## 使用方法

1. 将 EXE、运行所需 DLL、配置及模型文件放在同一目录；将仓库 `web/圣人视觉识别系统.html` 复制到 EXE 同目录。
2. 启动后无需输入本地 IP。窗口标题显示“网页访问IP：实际地址”；80 端口不可用时自动附带实际端口。多个网卡时优先选择已连接的以太网/Wi-Fi，完整地址列表可在“本机网络检查”查看。
3. 点击“打开本机调参”打开本机网页；其他设备使用标题中的地址，通过 HTTP 访问。网页文件缺失时显示“网页不存在”，补回文件后刷新即可。
4. 点击“点我开始记录人手数据”，在原生红蓝球窗口采集轨迹。累计数量从已有数据恢复，关闭重开后继续计数；镜像样本不重复计数。
5. 关闭采集窗口，点击“点我开始训练人手模型”。独立控制台使用 CPU 训练，默认 500 轮；完成后自动替换模型，主程序约 0.5 秒内检测并加载，无需重启。

## 数据与兼容性

| 文件 | 行为 |
|---|---|
| `人手数据/人手数据.txt` | 轨迹记录，可用记事本查看；内部保留坐标文本格式 |
| 旧 `mouse_data.csv` | 仅有旧文件时自动改名；新旧文件同时存在时使用新文件 |
| `人手数据/mouse.bin` | 训练成功后原子替换；模型结构为 2→64→32→20，大小 11,728 字节 |
| EXE 同目录 `mouse.bin` | 新位置不存在时兼容加载 |
| `网络自检.txt` | 本机 HTTP、网页可读性、访问地址和防火墙诊断；状态变化时更新 |
| `主机IP.ini` | 不再读取或生成 |

采集与训练使用 C++，无需 Python、Conda 或 PyTorch。仓库保留原 Python 脚本作参考。采集和训练使用同目录独占锁，防止并发读写；加载新模型失败时继续保留旧模型。

## 启动与网络处理

- 先显示主窗口，再后台检查 Makcu。未插设备时跳过驱动安装、硬件扫描和串口等待；检测到设备但无可用串口时才进行修复。
- HTTP 首选 8888；不可用时尝试 8889~8898，再由系统分配可用端口。同时尝试 80，便于直接访问 IP。
- 系统拒绝局域网绑定时尝试仅监听 `127.0.0.1`。所有监听均失败时在诊断中提示，主界面继续运行。
- 后台为当前 EXE 的实际 TCP 端口配置入站允许规则，适用域/专用/公用网络，来源限本地子网。
- 检查防火墙/BFE 服务、组策略、阻止所有入站设置及当前 EXE 的阻止规则；不关闭防火墙、不删除已有阻止规则。
- 约每 5 秒检查本机 HTTP、网页可读性和网卡地址，窗口标题随地址变化更新。HTTP 探测验证服务标识及当前进程 PID。
- 网页使用同源 `/config.js` 和 `/api`，远端浏览器不会误连自己的回环地址；HTML 修改后刷新生效。

本机自检不等于远端连通性验证。同一子网、路由器客户端隔离、访客 Wi-Fi、VPN、浏览器代理、第三方安全软件及管理策略仍可能影响其他设备访问。程序只检查可在运行机器上确定的状态。
