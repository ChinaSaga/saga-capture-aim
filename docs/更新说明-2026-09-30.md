# 2026-09-30 更新说明

本次更新修复部分 MAKCU 设备在鼠标按键时被误判断开的问题，并将诊断合并为有容量上限的异步运行日志。

## MAKCU 按键兼容修复

此前部分固件发送带前缀的二进制按键报文，程序仍要求完整命令提示符，或将 `km.buttons()` 后的换行误判为协议异常，导致按左键、右键后显示“MAKCU 已断开”。本次按完整报文边界更新按键状态，用户已确认实际设备修复成功。

解析器现在兼容：

- 裸二进制按键 mask，范围为 0～31。
- `km.<mask>`、`km.buttons<mask>` + CRLF；后面可带旧固件的 `>>> ` 提示符。
- `km.buttons()` + LF 或 CRLF + 二进制 mask + CRLF + 可选提示符。

其中 `<mask>` 为一个二进制字节，不是数字文本。带前缀的按键报文收到尾部 CRLF 才完成，不再强制等待提示符；命令 ACK 仍按其完整尾部处理。裸字节 10 和 13 保留为合法按键组合，头部和尾部换行不会产生多余的按键事件。非法头部、超范围 mask 和错误尾部仍按协议异常处理。

故障路径保留断开原因、可取得的 Windows/串口错误码，以及被拒绝字节附近的一小段十六进制数据，便于继续排查固件差异。正常按键不记录日志。

## 日志合并及自动清理

启动、驱动、串口故障、网络变化和模型加载诊断统一写入 EXE 同目录的 UTF-8 `运行日志.txt`。业务线程将低频诊断放入内存队列，后台线程以约 250 毫秒的窗口批量写盘；正常推理、鼠标移动和按键不逐帧记录。

| 项目 | 规则 |
|---|---|
| 行数 | 超过 2000 行清理旧内容，保留最近 1000 行 |
| 文件容量 | 同时限制在 1 MiB 内，较大记录可能使保留行数少于 1000 |
| 待写队列 | 最多 1024 条或 256 KiB；满时丢弃较旧记录，并记录丢弃数量 |
| 文件占用或写入失败 | 当前批次可能丢失；业务线程不等待磁盘恢复 |
| 网络检查 | 完整最新报告保存在内存；内容变化时才进入日志 |

不再生成 `SagaApp_startup.log`、`Makcu驱动报告.txt`、`Makcu串口日志.txt` 和 `网络自检.txt`。已经存在的旧文件不自动删除，需要时可手动清理。`人手数据.txt` 和训练窗口的进度输出继续保留。

日志是排错辅助资料，不能保证强制结束进程前的最后一批已落盘。本次没有新增端到端推理 FPS 测量，也不将后台异步写入描述为完全没有开销。细节见 [日志与性能](日志与性能.md)。
