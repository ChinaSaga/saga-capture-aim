# 构建与部署

项目使用 Windows、Visual Studio 18 Community（v145）、Windows SDK 10.0.26100.0，支持 x64 Release / Debug。源码位于 `src`，网页源文件位于 `web`。

## 构建入口

在项目根目录运行：

```powershell
./tools/build.ps1
# 调试配置仍使用项目固定的 Release 第三方运行库：
./tools/build.ps1 -Configuration Debug
```

该入口调用 `Saga.sln`，同时生成主程序和 ONNX 转 TensorRT 工具。Release 输出为：

- `x64/Release/圣人双机服务端.exe` 和对应 PDB。
- `x64/Release/ONNX转TRT工具.exe` 和对应 PDB。
- 运行时 DLL、第三方许可证及 `圣人视觉识别系统.html`。

`RuntimeDependencies.targets` 在每次构建后校验并复制依赖及网页，未变化的文件不重复复制。网页源文件缺失会使主程序构建报错。需要编辑网页时修改 `web/圣人视觉识别系统.html`，再运行构建。

## SDK 与运行库

`Dependencies.props` 是应用、转换工具和性能测试的路径来源，`dependencies.lock.json` 固定下载校验值与来源。

| 组件 | 项目目录或配置 |
|---|---|
| NCNN 20260526 | `.deps/ncnn-20260526/x64` |
| OpenCV 5.0.0 | `.deps/opencv-5.0.0/opencv/build` |
| ONNX Runtime 1.30.0 / DirectML | `.deps/onnxruntime-dml-1.30.0`，包含 CPU 与 DirectML provider |
| DirectML 1.15.4 | `.deps/directml-1.15.4-x64` |
| TensorRT 11.3.0.99 | `.deps/tensorrt-11.3.0.99` |
| CUDA 13.4 | `CUDA_PATH` 或 `SagaCudaDir`；运行库可用 `SagaCudaRuntimeDir` 指定 |
| Asio 1.38.2 | `src/Makcu/cat/asio/include`，纯头文件 |
| VC / OpenMP 运行库 | 按 MSVC 工具集从 Redist 自动部署 |

首次准备环境可运行：

```powershell
./tools/install_dependencies.ps1 -Python 'C:/你的Python/python.exe'
./tools/install_tensorrt.ps1
./tools/build.ps1
```

ONNX Runtime 的 DirectML 版本由源码构建，耗时可能较长，隔离工作目录由脚本自动创建。CUDA 完整 Toolkit 以外的头文件方案见 `tools/prepare_cuda_headers.ps1`；头文件不能替代运行时 DLL。SDK、模型及下载缓存不入库。

## 运行文件与用户数据

主程序直接从 EXE 所在目录读取网页、配置和运行库，不依赖 `.workbuddy`、Git 历史、历史备份或旧实验结果。

识别模型放在 `模型数据`，人手模型优先读取 `人手数据/mouse.bin`，兼容旧根目录的 `mouse.bin`。当前配置为 `圣人自用.js`、`配置保存.ini`、`CAT盒子.ini`，用户命名配置位于 `配置保存`。这些是当前功能数据，不属于可丢弃的备份。

没有配置文件时由程序生成默认配置。普通 NCNN / ONNX 使用不要求启动 NVIDIA 引擎。转换工具和 TensorRT 的支持范围见 [TensorRT 使用说明](TensorRT使用说明.md)。

## 编译与资源约束

- 主程序保持 `/source-charset:utf-8 /execution-charset:.936`：源码 UTF-8、内部文本 GBK、对外 UTF-8；路径使用宽字符 API。独立转换工具使用 Unicode。
- Release 保持 AVX2、`/O2 /Ob3 /Ot`、LTCG、`/MD`、`/EHsc` 和 fast FP；人手训练模型单独使用 precise FP。不能随意重排浮点运算。
- 主程序清单要求管理员权限。MSBuild 通过工程的 UAC 设置生成唯一清单，不能向 `DriverRes.rc` 再加入 RT_MANIFEST。
- `src/drv` 中 9 个驱动文件由 `DriverRes.rc` 打包，不得修改字节、换行或签名。准备驱动资源使用 `tools/extract_driver.py`。
- NCNN 第三方头文件的 C4251 / C4273 警告是已知构建警告；项目改动不应新增其它编译错误。

## 验证入口

无需连接采集卡的回归：

```powershell
./tools/test_review.ps1 -SkipCapture
node tools/test_web_profiles.cjs
```

第一条编译并运行隔离原生测试和无浏览器网页测试，跳过 `test_capture_*`。它包含模拟输入、合成像素、HTTP 回环和进程守护测试，不启动正式主程序。第二条需要 Node 的 `jsdom` 包可解析（例如配置 `NODE_PATH`），覆盖完整网页初始化、三组配置和交互。

`tools/test_wide_search.cpp` 包含 6,000 组随机合并结果对照和局部性能基准。断言在测试构建中保持启用。单项可用 `tools/build_performance.ps1 -Source tools/测试名.cpp -Name 测试名` 编译。

测试输出位于新建的 `.workbuddy` 子目录；需要写运行日志的测试必须保持隔离，不能在正式部署目录运行。全部测试工具仍保留，输出和临时目录可在测试完成后删除。采集卡实机工具仅在明确需要时另行运行。

## 常见排错

- 缺 DLL：检查构建输出及 `Dependencies.props`，不要从不明 PATH 目录混用版本。
- 中文乱码：检查主程序字符集及 GBK / UTF-8 边界。
- 网页不存在：重新构建，确认 HTML 与 EXE 位于同一目录。
- 模型加载失败：查看模型名、引擎、实际路径及 `运行日志.txt`，不要通过改采集参数掩盖模型错误。
- 资源重复：检查清单是否同时由工程和 RC 文件提供；资源修改后重新生成。
