面向「要把这个项目重新编译出来」的人。环境是 Windows + Visual Studio 18 Community（MSVC 14.51.x），
目标只有 **x64**，字符集 MultiByte，无 Git 仓库。

## 3. 方式一：MSBuild（首选）

```powershell
cd D:\C++采集卡源码
& 'C:/Program Files/Microsoft Visual Studio/18/Community/MSBuild/Current/Bin/MSBuild.exe' `
    SagaApp.vcxproj /p:Configuration=Release /p:Platform=x64 /m /v:minimal /nologo
```

- 产物：`x64\Release\圣人双机服务端.exe`（TargetName 已改，别找 SagaApp.exe）+ `圣人双机服务端.pdb`
- 构建结束后 `RuntimeDependencies.targets` 自动把所有运行时 DLL 和 DirectML 许可证拷进 `$(TargetDir)`；
  任一 DLL 缺失会直接报错并列出路径。
- 已知警告：NCNN 头文件 `C4251` / `C4273`（dll 接口导出 STL 成员），**不影响构建成功**，不用修。

## 4. 方式二：手工 cl.exe / link.exe（MSBuild 被安全策略拦住时）

```bash
bash "D:/C++采集卡源码/.workbuddy/build.sh"
```

- 产物：`.workbuddy\build-x64\圣人双机服务端.exe` + `.pdb`，并自动从上面同一批路径复制运行时 DLL。
- 差异点：**不启用 `/GL` + `/LTCG`**（全程序优化只在 MSBuild 那条路上），其余 Release 关键开关一致。
  做性能对比请用 MSBuild 的产物。
- 2026-09-27 实测：15 个 TU 全部编译通过、链接 rc=0，产物 527,872 字节 + 2.0 MB PDB，无致命错误。
- 清理：`.workbuddy\build-x64\` 可直接删，跑一次脚本就重建。

## 4.5 资源与提权清单（两条构建路径都要管）

EXE 里有两类资源，**归属不同**，这是踩过坑之后特意分开的：

驱动文件来自官方包 `CH343SER.EXE`，它的自解压脚本支持静默解包，**不用装 7-Zip / WinRAR**：

```bash
CH343SER.EXE -s2 -d<目标目录>          # -s2 = 不显示任何界面
```

> 解包后会顺带拉起 WCH 的图形安装器 `DRVSETUP64.exe`，我们不用它（直接 pnputil 装 INF），
> 结束掉即可。仓库里备了脚本：`.workbuddy\extract_driver.py`（解包 → 复制到 `src\drv\` → signtool 复核）。

| 资源 | 谁提供 | 类型 / ID |
|---|---|---|
| `src\drv\` 下 9 个驱动文件 | `src\DriverRes.rc`（两条路都用） | RCDATA，ID 401~409 |
| 提权清单 | MSBuild：vcxproj 的 `EnableUAC` + `UACExecutionLevel`<br>手工脚本：`src\AppManifest.rc` + `src\app.manifest` | RT_MANIFEST(24)，ID 1 |

⚠ **清单只能有一份**。一开始把 RT_MANIFEST 也写进 `DriverRes.rc`，结果 MSBuild 自己又生成一份，
链接期直接报：

```
资源重复。类型: MANIFEST，名称: 1，语言: 0x0409     (CVT1100)
转换到 COFF 期间失败: 文件无效或损坏                 (同一个原因引起的连带报错)
```

所以现在的分工是：**MSBuild 那条路完全不碰清单资源**（交给工具链），手工脚本才编 `AppManifest.rc`。
别再把清单加回 `DriverRes.rc`。

⚠ 另一个必须记住的坑：**`RT_MANIFEST` 得自己定义成 24**。rc.exe 不认识这个宏（它在 winuser.h 里），
不定义就会把 "RT_MANIFEST" 当**字符串型**资源名写进去，Windows 只认数字型 24 → 清单静默失效、
程序不提权，而且编译链接全都不报错。`AppManifest.rc` 里已经写了 `#define RT_MANIFEST 24`。

手工脚本另外两点：要用 `rc.exe` 先把 `.rc` 编成 `.res` 再链接；
编 `DriverRes.rc` 时**必须 `/i` 指到 `src` 与 `src\drv`**，否则里面的相对路径找不到文件。

验证清单真的进去了（不用装工具）：

```bash
python -c "
import struct;d=open('x64/Release/圣人双机服务端.exe','rb').read()
pe=struct.unpack_from('<I',d,0x3c)[0];opt=pe+24;magic=struct.unpack_from('<H',d,opt)[0]
dd=opt+(112 if magic==0x20b else 96);rva=struct.unpack_from('<I',d,dd+16)[0]
n=struct.unpack_from('<H',d,pe+6)[0];sh=opt+struct.unpack_from('<H',d,pe+20)[0]
secs=[struct.unpack_from('<IIII',d,sh+40*i+8) for i in range(n)]
off=lambda r:[ptr+(r-va) for vs,va,rs,ptr in secs if va<=r<va+max(vs,rs)][0]
base=off(rva);print('资源类型:',[struct.unpack_from('<I',d,base+16+8*i)[0] for i in range(struct.unpack_from('<H',d,base+12)[0]+struct.unpack_from('<H',d,base+14)[0])])
print('含 requireAdministrator:', b'requireAdministrator' in d)
"
```

期望输出 `资源类型: [10, 24]`（10=RCDATA，24=RT_MANIFEST）且 `True`。

> 改了资源/清单相关的东西之后，**先清一次中间目录再生成**（VS 里"重新生成"，或删掉中间目录），
> 免得旧的 `.res` 残留造成莫名其妙的链接错误。

## 4.6 常见的几个链接期报错

| 报错 | 原因 / 处理 |
|---|---|
| `资源重复。类型: MANIFEST，名称: 1，语言: 0x0409` | 有两份清单。确认没有再往 `DriverRes.rc` 里加 RT_MANIFEST；MSBuild 只留 vcxproj 的 EnableUAC |
| `转换到 COFF 期间失败: 文件无效或损坏` | 多半是上面那条的连带错误；也可能是中间目录残留旧 `.res`，清一次中间目录重新生成 |
| `LNK1158: 无法运行"mt.exe"` | 手工链接用了 `/MANIFESTINPUT`。别用它，走 `AppManifest.rc` + `/MANIFEST:NO` |
| `"WinMain"的批注不一致 (C28251)` | 开了代码分析时的无害告警，可忽略 |
| `"e": 未引用的局部变量 (C4101)` | `src\Makcu\cat\src\cat_net_core.cpp` 第三方代码的告警，可忽略 |

## 5. 编译开关与「为什么不能改」

| 开关 | 值 | 原因 |
|---|---|---|
| 字符集 | `/source-charset:utf-8 /execution-charset:.936` | 源码 UTF-8、中文常量编成 GBK。**改成 `/utf-8` 会让内部比较全崩**（见：[架构与源码索引](架构与源码索引.md#编码体系)） |
| 指令集 | `/arch:AVX2` | `Mouse.cpp`、`NCNN.cpp`、`CapturePixels.h`、`TensorPixels.h` 有 AVX2+FMA 内联指令 |
| 异常 | `/EHsc` | `Makcu\` 里有 try/catch（原 DLL 工程没开，属历史隐患） |
| 浮点 | `/fp:fast` | 推理预处理/后处理的微基准基线。`114/255` 常量折叠曾产生 1 ULP 差异，改动需重新对齐 |
| 运行库 | `/MD` | 与第三方 Release 库一致；EXE 依赖 VC 运行库 DLL |
| 优化 | `/O2`、`/Ob3`、`/Ot`、`LTCG`（Release） | `/Ob3` 经 AdditionalOptions 启用，不要再显式写 `/Ob2` 造成重复 |
| 安全检查 | SDL / GS / CFG 全部 **false** | 用户明确要求优先速度；改回会明显影响热路径 |
| 语言标准 | `/std:c++20`，`ConformanceMode=false` | 不开 `/permissive-`：vendored asio 在严格模式下没验证过 |

## 6. 部署

程序按「EXE 所在目录 = 运行目录」工作（`GetModuleFileNameA` 取目录），不读注册表、不装环境。

1. 把构建产物连同 `x64\Release\` 下的 **所有 DLL** 拷到目标目录
   （常规部署目录：`D:\BaiduSyncdisk\圣人自用V11\`）。
2. 补用户数据：`mouse.bin`、模型文件（`三角洲行动.param` / `.bin` / `.onnx`）。
3. 首次运行会生成：`圣人自用.js`（按默认值写出）、`主机IP.ini`、`配置保存.ini`、`SagaApp_startup.log`。
4. 端口：HTTP 固定 **8888**（启动时由 `configApplyStartupDefaults()` 强制覆盖配置值，这是对齐易语言原版的行为），
   UDP 收图 **6666**。网页端在外部：`D:\BaiduSyncdisk\圣人自用V11\圣人视觉识别系统.html`。

> ⚠ 不要把 `x64\Release\圣人自用.js` 当发布配置带走——它是跑一次之后写出的全 0 默认值版本。

## 7. 排错速查

| 现象 | 原因 / 处理 |
|---|---|
| 缺 DLL 弹框后退出 | `missingDeps()` 检查 `DirectML / ncnn / onnxruntime / opencv_world4120`。把对应 DLL 放到 EXE 同目录 |
| 「mouse.bin不存在」 | 轨迹文件缺失；从 `D:\BaiduSyncdisk\圣人自用V11\mouse.bin` 拷一份 |
| 「http启动失败!」并退出 | 8888 端口被占用（通常是上一个实例没退）。关掉进程或改 `圣人自用.js` 里的 `本地端口`（代码会再覆盖回 8888，见上文） |
| LNK2001 找不到系统 API | 手工 link 必须显式列出 `kernel32/user32/gdi32/ole32/oleaut32/uuid/advapi32/ws2_32/setupapi` 等库（脚本里已列全） |
| 编译期找不到 `<immintrin.h>` 相关指令 | 忘了 `/arch:AVX2`，或改成了 Win32 工具链 |
| 中文显示乱码 | 检查是否误用 `/utf-8`；设备名/配置读写跨越 `ansiToUtf8`/`utf8ToAnsi` 两条边界 |
| NCNN 一堆 C4251/C4273 | 正常，第三方头文件导出 STL 成员导致 |
| 改了 `圣人自用.js` 的端口没生效 | 设计如此：启动时强制 8888 |
| 起不来也没日志 | 看 `SagaApp_startup.log` 停在哪一步 `[01]`~`[13]`，按编号对照 `src\main.cpp` |
