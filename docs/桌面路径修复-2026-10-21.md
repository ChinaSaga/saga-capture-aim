# 桌面部署与模型读取修复（2026-10-21）

程序仍按 EXE 所在目录定位资源。整体移动软件文件夹到桌面时，DLL、网页、配置和“模型数据”应一起移动；桌面快捷方式只负责启动文件夹中的 EXE。

## 修复内容

- 启动目录改为 `GetModuleFileNameW`，消除 ANSI 转码丢失和 `MAX_PATH` 截断。模型枚举、NCNN/ONNX/TensorRT、人手模型、配置、INI、声音和截图的文件路径使用宽字符。
- 内部文本仍使用 GBK，HTTP/JS 配置仍为 UTF-8；转换明确指定 CP936，不再随 Windows 当前代码页变化。
- NCNN 使用宽字符打开的 FILE 流；ONNX 直接传入宽字符路径；TensorRT 和人手模型提供宽字符加载入口，保留原窄字符接口用于既有工具。
- ONNX 缺少可选类别文件时无需写入模型目录。只读模型目录可用于读取模型。
- 模型目录缺失、同名普通文件占位、权限拒绝和枚举失败返回 HTTP 500，携带实际目录和 Windows 错误；可读取但没有模型的目录才返回空列表。网页显示详细错误并支持修复后刷新恢复。
- 配置保存/删除失败不再返回成功；网页显示配置操作错误。INI 读取兼容旧 GBK、UTF-8 BOM 和 UTF-16 LE，首次保存旧格式时保留内容并原子替换为 UTF-16 LE，避免 UTF-8 系统模式下中文写入错误 87。
- 管理员启动清单继续使用 `requireAdministrator`。不修改桌面或系统目录 ACL，不关闭系统安全功能；真正的访问拒绝会明确报告。

## 验证

```powershell
./tools/build.ps1
./tools/test_desktop_paths.ps1
```

原生模型加载测试需要 `x64/Release/模型数据/三角洲416.param`、`.bin`、`.onnx`，以及 `x64/Release/人手数据/mouse.bin`。这些模型属于本地数据，不提交到版本库。

验证覆盖：

- Unicode 目录（中文、空格、emoji）、超过 260 字符的目录、启动工作目录改变。
- 真实 NCNN/ONNX CPU 模型及人手模型加载；TensorRT 的宽字符文件打开和无效内容诊断。
- 模型目录缺失、目录被文件占用、临时测试目录显式拒绝读取时的错误码 5，以及权限恢复后的刷新。
- 配置读写、命名配置保存/导入、只读文件、旧 INI 迁移及损坏文件保留。
- 默认系统代码页和仅测试进程使用的 UTF-8 ACP；测试不会修改系统区域设置。
- 网页脚本语法、具体错误与目录显示、刷新恢复和可用引擎按钮。

测试不启动采集卡、驱动安装或鼠标控制服务；未进行完整采集/推理/鼠标链路实机验收，也未重新执行 TensorRT GPU 推理。
