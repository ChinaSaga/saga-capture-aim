## 2. 易语言语义坑（翻译/对齐时反复踩过）

| 易语言写法 | 真实语义 |
|---|---|
| `÷` | **实数除法**；整数除法是「整除」（`\`） |
| `取整()` | **向下取整 floor**（-7.8 → -8）；向零截断是「绝对取整」 |
| 小数 → 整数变量赋值 | **四舍五入**（不是截断） |
| 颜色值 | **BGR 打包整数**：`R = v & 0xFF`、`G = (v>>8)&0xFF`、`B = (v>>16)&0xFF` |
| 子程序局部（非 static）变量 | 跨循环迭代保持值，不重置 |
| 数组下标 | 从 **1** 开始；`分类ID + 1` = 类别号 1~10 |
| `内存画板.清除()`（背景透明） | 实际是 `GdipGraphicsClear → 黑` |
| `定位写出` | `TextOutA`，用 DC 文本色/背景模式，**与画笔色无关** |

## 3. 与原版易语言的已知差异（低优先级，未对齐，改动前先问）

- **界面字体**：原版是 12 点宋体（96 DPI 下 ≈ **-16px 宋体**），C++ 用的是 `-16 Microsoft YaHei UI`。
- **画板文字**：原版从未设置文本色/背景模式 ⇒ 默认黑字 + `OPAQUE` 白底；C++ 显式用了深色 + `TRANSPARENT`。
- **初始化后自动枚举一次编码**：易语言原版每次点「开始采集」都会再启动一次线程；C++ 只在只检测到 1 个设备时补一次枚举。
- **有意做得比原版稳的地方**：重复点「开始采集」只起一次线程；切换识别范围不需要重开程序。
- **程序现在要求管理员权限**（2026-09-29 起）：清单 `requireAdministrator`，为的是能静默安装 Makcu 盒子的
  CH343 驱动。原版易语言程序是不提权的 —— 这属于**有意的行为变更**，代价是每次双击 EXE 会弹一次系统 UAC。
- 原版 `接口_初始化默认设置()` 会把本地端口强制成 8888 —— C++ 已用 `configApplyStartupDefaults()` **复刻了这个行为**。

## 4. 历史性能优化结论（有权衡、不要再动方向）

三轮采集/预处理优化（2026-09-27，x64 Release）：

| 轮次 | 主要改动 | 实测 |
|---|---|---|
| 第一轮 | 统一输出 top-down BMP；推理走原始 BGR 直投（去掉整帧复制与 `imdecode`）；NCNN/ONNX 融合预处理；关 SDL/GS/CFG | 预处理微基准 160→3.4×、320→12.9×、640→10.9×（**只覆盖像素/归一化，不含 GPU 与端到端**） |
| 第二轮 | 预览/截图直接用帧引用；体槽池 4→8；NCNN 后处理 AVX2 分块 + 到 99 提前停 | 6 组预览像素与 JPEG95 字节完全相同 |
| 第三轮 | 生产者锁与快照锁分离；YUY2/P010 三次 16B 写入；AVX2 8 像素预处理；后处理寄存器内阈值过滤 | 6,240 组 YUV 精确对照；36,000 帧选靶结果一致；局部 NMS 约 -11%（**不得外推成整机 FPS**） |

- **AimLock 专项**：只砍「重选时才用到的候选计算」与 O(n²) 无效配对，头身公式/阈值/记忆全部保留；
  36,000 连续帧选中结果与完整记忆字段一致。
- **Release 编译选项实测**：已确认 `/Ob3` + AVX2 + fast FP + LTCG + `/MD`，AVX-512 在部分追踪场景**更慢**，未采用。
- **Makcu 实机（COM3，CH343）**：
  - 命令提交 → Windows Raw Input 收到移动：100 次，中位 **0.8196 ms**、P95 1.4466 ms、最大 1.7167 ms；
  - `Device` 移动发送函数：中位 0.0545 ms；`km.version()` 往返：中位 0.2941 ms；
  - 10,000 条零位移发送 + 10 次重连无失败；flush 对照无明显收益。
  - 以上**仅覆盖串口调用到系统报告**，不含采集/推理/完整轨迹。
- **端到端尚未实测**：真实模型的三条链路（NCNN Vulkan / ONNX DirectML）还没跑过采集卡→鼠标的整链帧率。

| 7 | `use_int8_inference` / `fp16_*` 无条件开启 | 对非 int8、精度敏感模型可能掉点；`num_threads=1` 是刻意的（GPU 路径） |
| 8 | Cat（网络键鼠）未启用 | 代码已编进来并导出 C API，应用层没调用 |
| 9 | ~~遗留中间产物~~（2026-09-27 已清理） | 删除了 `SagaApp\x64\Release\`（旧 IntDir，69 MB）与 `src\Makcu\makcu-cpp\`（第三方样例工程输出，32 MB）。保留 VS 自己的 `.vs\` 缓存（243 MB，IDE 自动重建） |
| 10 | 移动消费事务、暂停/断帧触发撤销 | Makcu 审查里提出过，尚无独立专项 |
| 11 | CH343 驱动自动安装已在**彻底干净状态**下实测通过（2026-09-29）：`pnputil /delete-driver oem244.inf /uninstall /force` 清空后运行程序，日志出现 `[drv] 未检测到可用驱动 → 开始从 EXE 资源安装` → `pnputil /add-driver 退出码=0` → `[05b] …（本次已安装）`，驱动包重新注册成功 | 还没做的一步：**真盒子插上后是否自动绑定并出现 COM 口**（需要物理插一次）。插上后看设备管理器「端口(COM 和 LPT)」有没有 `USB-Enhanced-SERIAL CH343`，日志里 `[drv]` 会写"盒子已识别为 COMx" |
| 12 | 驱动安装失败时临时目录会保留 | 失败时故意不删（`%TEMP%\SagaMakcuDrv_<pid>\`），方便按日志里的路径手动 `pnputil` 重试；日志同时记录了 pnputil 的完整输出 |
| 13 | 装完不拔插就能用：**要 `UpdateDriverForPlugAndPlayDevices` + `CM_Reenumerate_DevNode`** | 官方 SETUP.EXE 的字符串里就写着 "安装成功!UpdateDriverForPlugA…"，导入表里还有 `SetupCopyOEMInfA` / `SetupDiCallClassInstaller` / `SetupInstallFilesFromInfSectionA` / `CM_Locate_DevNodeA` / `CM_Reenumerate_DevNode`。只跑 `pnputil /add-driver` 等于"把驱动包放进系统"，不会装到已在场的设备上，所以得靠拔插。现已补上这两步 |
| 14 | 官方安装器的「卸载」按不动 ≠ 装失败 | SETUP.EXE 里 `"无设备驱动可卸载!"` 是它枚举**当前在场**设备后的结论：盒子没插（或插在别的机器上）时必然报这句，与驱动包装没装无关。**只有在盒子插着的那台机器上点它才有意义** |
| 15 | 「驱动包在系统里」≠「驱动可用」（已修） | 踩过：WCH 安装器点卸载会删掉服务与 `System32\drivers\CH343S64.SYS`，但**驱动包仍留在 DriverStore**；早先只查包就误判成"已装好"，于是既没安装也没提示。现在按「串口在不在 / 服务键+sys 文件」判断，见 `src\DriverSetup.cpp` 文件头 |
| 16 | 日志串行错乱（已修） | `DriverSetup.cpp` 曾经自己 `fopen` 一份启动日志，与 main.cpp 的句柄互相覆盖、把 `[drv]` 行写花。现在统一通过 `runtime_log` 内存队列，由一个后台线程批量写 `运行日志.txt`；业务线程不直接操作文件句柄 |
