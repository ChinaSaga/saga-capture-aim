# 自适应截图与模型组

主程序扫描 `EXE目录\模型数据\` 的直属子文件夹，将文件夹名称作为网页中的模型组名称。选择标有“自适应”的模型组后，按当前推理引擎自动枚举并加载组内 160～640 之间、32 的整数倍尺寸模型（共 16 个候选档位），并在首次使用前预热。根目录的单文件模型保留原来的固定截图范围用法。

例如：

```text
模型数据\
  三角洲行动\
    160.onnx   192.onnx   224.onnx   ...   640.onnx
    160.trt    192.trt    224.trt    ...   640.trt
    160.param  192.param  224.param  ...   640.param
    160.bin    192.bin    224.bin    ...   640.bin
```

合法档位为：160、192、224、256、288、320、352、384、416、448、480、512、544、576、608、640。只需准备所用引擎的文件，允许部分档位缺失；不自动生成模型。NCNN 必须有同尺寸的 `.param` 和 `.bin`；ONNX 使用 `.onnx`；N卡专用使用 `.trt`。网页显示“三角洲行动（自适应）”，保存的模型名称仍是“三角洲行动”。各引擎分别检查文件，只要有一个完整尺寸即可启用对应按钮，无需 640；缺少所需的小尺寸档位时，使用不小于所需范围的最小可用尺寸，超过所有尺寸时使用最大可用尺寸。不同引擎之间不会自动切换。文件名应与模型实际输入尺寸一致，同组应使用相同的类别定义；ONNX 需固定输入尺寸，类别文本可放在组内 `空类别.txt`。

## 切换规则

距离以源画面像素为单位，使用准星到当前锁定位置（包含已设置的锁定位置偏移）的二维直线距离。启用准星追踪且只识别到一个准星时使用该准星，否则使用截图中心。裁剪始终以画面中心为中心。

默认搜索范围和自适应上限由当前模型组、当前推理引擎成功加载并预热的最大尺寸决定。未按住自瞄热键或没有锁定目标时使用该最大尺寸。按住热键且有目标时，使用上一帧锁定目标的距离、完整目标框宽高和位置，决定下一帧范围；只从可用档位中选择，并限制在该组实际的最小、最大档位之间。

例如只有 `320、416、512` 时，启动、松键或失锁均使用 `512`，按住热键后可在这三档间自适应；只有 `320` 时，无论是否按键、目标大小或距离如何，都使用 `320`。同一文件夹内 ONNX 和 TRT 拥有的最大尺寸可以不同，各自独立处理。

距离仍提供基础范围：选择半边长严格大于目标距离的最小档位，计算式为 `32 × (floor(距离 / 16) + 1)`，再限制在支持的 160～640 内。下表只表示距离要求，最终范围还会根据目标框放大，并受实际最大可用档位限制。

| 目标距离（按住热键） | 所需尺寸（缺档再向上回退） |
|---|---|
| 0～小于 80 | 160 × 160 |
| 80～小于 96 | 192 × 192 |
| 96～小于 112 | 224 × 224 |
| 每增加 16 像素 | 再增加 32 的尺寸档位 |
| 144～小于 160 | 320 × 320 |
| 160～小于 176 | 352 × 352 |
| 192～小于 208 | 416 × 416 |
| 大于等于 304 | 640 × 640 |

目标框在左右两侧各留出框宽的 10%、上下两侧各留出框高的 10%，每侧至少 16 像素。按以画面中心裁剪的方式计算容纳整个目标框及余量所需的正方形，将结果向上取整到 32 的倍数，并与距离要求取较大值。因此即使锁定点已在准星中心，大目标也不会一直挤在小截图里。

| 上一帧目标框（居中，按住热键） | 目标框要求的范围 | 只有 256 / 320 / 416 / 640 时 |
|---|---|---|
| 100 × 100 | 160 × 160 | 256 × 256 |
| 250 × 250 | 320 × 320 | 320 × 320 |
| 256 × 256 | 320 × 320 | 320 × 320 |
| 320 × 320 | 384 × 384 | 416 × 416 |
| 500 × 500 | 608 × 608 | 640 × 640 |

目标框偏离画面中心时，范围会进一步增加以容纳远侧边缘。准星追踪和锁定位置偏移只参与距离计算，目标框的容纳范围仍依据画面中心，不会错误地随准星移动。框距当前图片任一边缘不超过 8 像素时，视为可能被截断，下一帧尝试当前范围的 1.2 倍（向上取整到可用档位，并以最大可用档位封顶）；如果新画面中仍贴边，就继续放大，直到该组上限。超过最大范围的目标不能保证完整容纳。

升档立即用于下一帧；降档要求同一个更小的可用档位连续 3 帧都适合，避免单帧框尺寸波动导致反复切换。松键、失锁、模型或引擎切换会清空缩小确认状态；松键和失锁无需等待，直接回到最大可用档位。每帧仅检查已预加载的可用档位并执行一次模型推理，不逐档试推理，也不重新扫描磁盘。实际速度与识别效果取决于模型和场景，不以档位承诺固定 FPS 或准确率。

“吸附常驻”仍按原规则控制移动，但未实际按键时保持最大可用搜索范围。新范围从后续采集帧生效；模型缓存、截图尺寸和坐标一起切换，切换裁剪不重启采集卡，也不反复读取模型文件。主程序顶部及“中心识别范围（像素）”下方新增的“当前截图范围”显示实际尺寸。“中心识别范围”下拉框独立保存单模型手动范围，自适应模式下禁用且不跟随实时尺寸变化；切回单独模型后恢复下拉框，并按保存的手动范围进行本机截图和推理。界面复用 500 毫秒定时器，实时范围仅在数值变化时更新文字，不在推理线程发送界面消息。网页模型列表显示当前引擎发现的档位及最大尺寸，实时尺寸显示实际正在使用的范围，复用既有每秒状态请求，也只在文本变化时更新。

某个尺寸加载、预热或推理失败时记录到 `运行日志.txt`，停止使用该尺寸，并重新以剩余可用模型中的最大尺寸作为搜索范围和上限；所有尺寸均不可用时才停止该组推理。修复后切换一次推理引擎重试。初次准备多个档位模型可能比单模型耗时更长，并占用更多内存或显存。

本机采集卡直接裁剪原始采集帧。使用 UDP 图片输入时，发送端画面的宽高至少达到当前组最大可用尺寸，接收端再按所需范围中心裁剪。例如最大为 512 时可提供 512 × 512，只有 320 时可提供 320 × 320，不再统一要求 640 × 640。

## 验证

`test_model_files` 验证目录分组、NCNN 配对、无 640 的模型组、16 个档位的距离阈值和向大尺寸回退；`test_adaptive_capture` 验证目标大小、边缘余量、截断后连续放大、准星偏移、降档确认和异常框处理；`test_adaptive_loop` 使用生产推理循环和模拟帧验证三个引擎按目标大小切换全部档位、预热只执行一次、缺档回退、最大 512、单独 320、最大模型失败回退、失锁恢复和松键恢复；`test_capture_preview` 验证各档位实时文字、手动选项与自适应显示分离，以及尺寸不变时不重复写控件；`test_capture_pipeline` 验证所有档位连续裁剪切换的像素、BMP 头和已借出帧不被改写。`test_adaptive_models` 可传入实际模型组目录验证真实模型推理，以及模型文件不再可读时缓存仍能切换；可追加 `--gpu` 检查 NCNN/Vulkan 和 ONNX/DirectML。
