# 配置与运行时接口

## 1. `圣人自用.js`（主配置，EXE 同目录）

- **格式**：UTF-8（可带 BOM），每行 `键=值`，换行 **CRLF**；值可用 `"` / `'` 包裹。
- **读写**：`configInit()` 载入到哈希表；`configSyncAll(true)` = 「读 → 赋给全局 → 写回文件」。
  新增移动字段使用下述默认值；其它文件里没有的键 ⇒ 整型 0 / 浮点 0 / 空字符串（即 `App.h` 的默认值只在有特殊初值时才体现）。
- **两个例外**：`模型名称`、`移动延时` 读归读，但不写回缓冲区（复刻原版行为）。
- **启动即覆盖**：`configApplyStartupDefaults()` 会把 `本地端口` 强行写成 `8888`（对齐易语言原版），
  所以文件里改端口没用。8888 是首选值；运行时若不可用会自动换端口，实际地址见“本机网络检查”。

| 类别 | 键名 |
|---|---|
| 整型 | `本地端口`、`优先锁定`、`其次锁定`、`再次锁定`、`锁定范围`、`优先锁定位置`、`其次锁定位置`、`再次锁定位置`、`自瞄主键`、`自瞄副键`、`自瞄副键2`、`自瞄副键3`、`准星绑定1~4`、`扳机热键1~4`、`推理引擎`、`准星类别`、`开镜时间`、`开枪间隔`、`锁定频率`、`延时频率`、`目前阵容`、`中心点范围`、`移动延时` |
| 字符串 | `模型名称`（不写回）、`框内移动`、`线程移动`、`自瞄连续按下`、`自动截图`、`吸附常驻`、`准星扳机`、`中心扳机`、`type0~type9`、`team1type0~team1type9`、`team2type0~team2type9` |
| 浮点 | `置信度`、`准星精度`、`交并比`、`移动系数`、`扳机范围` |
| 额外写出 | `模型名称="…"`、`服务器ip="127.0.0.1"`（本地默认地址；网页实际连接当前浏览器地址，不依赖此字段） |

几个容易看错的语义：

- `推理引擎`：**1 = NCNN，2 = ONNX**。两个推理线程一直在跑，由这个值决定谁真正干活。
- 自动移动统一使用移动系数（0–10，缺失默认 0.618）；旧的移动方式、Kp、Ki 被忽略并在保存时移除。
- 旧预测器及卡尔曼实现、控件已移除。旧连续次数、各组 X/Y/共用提前量以及五个卡尔曼配置字段在保存时清理，旧网页 POST 会被拒绝。
- 唯一整数参数 `移动速度补偿` 范围 0–100，默认 0（关闭），支持 `热键2_`、`热键3_` 前缀及三组独立保存/导入。1–100 统一用 `s = 幅度/100` 连续增强预测追赶，不再以 50 分段；0 完全沿用原移动输出。各类别锁定位置、选靶和扳机仍基于实际检测。任意非零档位建立有效预测后均允许通过中心停移范围；尚未建立预测时继续观测，但保留中心停移。
- 补偿使用同一人物前后帧共有部位的配置锁定点差值，优先较大框，不能直接相减头身锁定点。无共有部位时清理追赶累积，但已建立的领先可继续使用命令速度平滑过渡，不凭不同部位的位置差启动新领先。完全丢失、松键、换人、配置/裁剪切换、异常位置跳变或超过 125 ms 的间隔清理历史；重复时间戳不推进补偿。
- 每轴至少三次同向有效观测，并持续 `max(16 ms, 预测窗口)` 才允许增加追赶补偿。预测窗口取实际帧间隔、本次推理耗时与平滑后的命令消费间隔中最大者的两倍，限定 8–80 ms。追赶与原移动函数都使用 `实际锁定偏差+领先量`，趋势包含领先量的变化；若该点的剩余偏差按当前变化趋势将在窗口内消除，则不加速，否则根据预测剩余距离自动设置补偿速度。使用较慢增长（80 ms 加两倍窗口）和较快回收（至少 8 ms）的时间常数，按实际帧间隔离散化。越过预测点立即清除旧方向追赶补偿，越过实际点不强制清除领先；100 ms 内反复变向会暂停追赶补偿 120 ms。
- 追赶速度以 `幅度 / 10 ms` 为上限，经 `剩余距离 / (剩余距离+8 px)` 缩放，再乘实测命令周期（至少当前帧间隔）得到等效补偿距离；二维向量长度不超过幅度值。追赶项按 `1-s` 留出前馈提供的速度份额，避免同一跟随速度被重复补偿。该距离乘原移动系数后，叠加在原 100 px 径向限幅后的鼠标输出上，故远距离也能加速。幅度是控制强度，不是已标定的鼠标计数或敌人真实速度。
- 消费线程完成一个有效移动批次时推进 `moveDispatchSequence`。允许一次轨迹跨越多次推理；追赶补偿在首次新消费前保持关闭，消费停滞超过四倍周期（限定 64–80 ms）后清零，避免长时间频率门控/线程阻塞期间蓄积，同时容忍低速时取整和中心判断造成的短暂零输出。可用下述连续可见运动重新建立领先。该序号表示命令消费，不是硬件移动成功确认。没有相机/鼠标响应标定，不能仅凭推理时间推导敌人真实速度；原系数与实际延迟已经造成的振荡不能由本参数保证消除。
- 在 `g_moveLock` 下记录实际消费批次的 X/Y 命令总量，与消费序号一起读取。160 ms 时间常数平滑净命令速度，35 ms 平滑屏幕残差变化，用持续跟随证据排除最初向静止目标拉动的方向。已建立的领先不按位置误差的正负翻转；因此目标可处于准星后方，前馈仍沿跟随方向输出。尚无新命令、但同一部位连续至少三帧/24 ms 移动且累计超过 3 px 时，可从中心停移区内启动。
- 各档名义领先量为 `平滑跟随速度 × 40 ms × s`，前馈为 `平滑跟随速度 × 实际命令周期 × s`，两者各自的二维向量长度均限于幅度值。预测时间在某档位固定，故跟随速度稳定后领先距离趋于固定，不根据累计误差或追踪时长继续增长；加减速后距离自动调整。该像素映射未作视角标定，实际领先量取决于帧率、灵敏度与运动速度，不是固定 100 px。前馈是鼠标命令单位，不再乘一遍移动系数。最终输出为 `原移动函数(实际锁定偏差+领先量, 移动系数) + 追赶补偿*移动系数 + 前馈`。移动系数为 0 时仍禁止输出。
- `中心点范围`：内部 `/100` 使用，**只对「优先锁定」那一档（`lockType == 1`）**生效；
  其次/再次/其它类别跳过停移判断，继续追。
- `优先锁定/其次锁定/再次锁定` 填的是**类别号 1~10**（对应检测 `label+1`）。
- 键鼠热键编号：1 左、2 右、3 中、5 侧键1、6 侧键2；**4 无效**（历史遗留，网页上的「热键4」恒为假）。

## 3. HTTP 网页与接口（`Net.cpp` / `WebAccess.cpp`）

网页使用外部 **`圣人视觉识别系统.html`**，必须与 EXE 放在同一目录，不再打包到 EXE 中。
当前使用的网页文件为 `D:\C++采集卡源码\x64\Release\圣人视觉识别系统.html`；编辑源码目录的 `web\圣人视觉识别系统.html` 后同步到此处。
运行时只按 EXE 所在目录查找。缺失时返回 HTTP 404 和“网页不存在”提示，同时停用调参接口；补回后刷新即可恢复。
网页内容每次访问时重新读取，更改 HTML 无需重新编译或重启 EXE。
网页模型列表只汇总 `EXE目录\模型数据\` 内实际存在的模型，名称为文件名去掉扩展名。同名文件控制当前模型的引擎按钮：`.onnx` 启用 ONNX，`.trt` 启用 N卡专用，配对的 `.param` / `.bin` 启用 NCNN；缺少文件的按钮变灰并禁止点击。打开网页或点击“刷新模型”时重新读取该文件夹，切换模型时更新按钮；不会扫描 EXE 根目录或其它子目录，也不会追加预设游戏名称或已删除的模型。
本机点击“打开本机调参”，会以 `http://127.0.0.1:实际端口/` 打开默认浏览器。
80 端口可用时，同一局域网的设备访问 `http://运行电脑的IP/`。
例如运行电脑的 IP 是 `192.168.1.136`，访问 `http://192.168.1.136/` 即可打开面板并调参。
服务优先使用 8888；不可用时依次尝试 8889~8898，再由 Windows 分配可用端口。
另尝试监听 80；不可用时使用带端口地址，不抢占已有服务。系统拒绝所有局域网绑定时尝试仅监听本机。
后台通过 Windows Firewall API 配置当前 EXE 实际使用的 TCP 端口，覆盖域/专用/公用网络，远端限制为 LocalSubnet。
“本机网络检查”显示内存报告，`运行日志.txt` 记录网络状态变化及配置结果，以及防火墙/BFE 服务、组策略、阻止入站和同程序阻止规则的检查结果。
后台每约 5 秒直接通过 Winsock 探测本机 HTTP，验证服务标识与当前进程 PID，并刷新网卡 IP、网页文件可读性；不依赖 DNS 或系统代理，也不阻塞主窗口。
本机探测通过不代表其他设备一定可达；路由器客户端隔离、访客 Wi-Fi、VPN、第三方安全软件和管理策略需按报告排查。
程序不修改防火墙全局开关、网络类型或路由器配置，不删除已有阻止规则。

- 手写 Winsock + `listen(16)`；每连接起一个线程，`Connection: close`。
- `GET /__saga_health` 返回服务标识与进程 PID，只用于本机诊断；即使 HTML 缺失也可用，不提供调参能力。
- `GET /` 或 `/index.html` 返回 EXE 同目录的 HTML；`GET /config.js` 返回当前参数生成的合法 JS，禁止缓存。上述接口均以同目录存在 HTML 为前提。
- `GET /api` 返回状态 JSON；`POST /api` 的 body 为 `cmd|arg`，UTF-8。仍兼容旧 `POST /`，以及携带 `Accept: application/json` 的 `GET /`。
- `GET /models.json?engine=1|2|3` 返回 `{"engine":3,"models":["三角洲行动"]}`，按引擎列出 `EXE目录\模型数据\` 内的模型名称（无扩展名）。仅扫描文件，NCNN 必须有同名 `.param` 和 `.bin`；无效或重复引擎参数返回 400，成功 200，同时返回 Unicode `directory` 字段指明实际读取位置，要求 EXE 同目录存在 HTML。
- `GET /model-catalog.json` 返回 `{"models":[{"name":"三角洲行动","engines":[1,2,3]}]}`，单次扫描“模型数据”文件夹，汇总同名文件及可用引擎，扩展名和名称匹配忽略大小写；仅有未配对 `.param` 或 `.bin` 时不视为可用模型。空文件夹返回空模型列表；目录缺失、被同名文件占用或访问被拒绝时返回 500 和 error/directory/code，不返回伪装的空列表。网页据此建立模型列表、启用对应引擎按钮，成功 200，同时返回 Unicode `directory` 字段指明实际读取位置，要求 EXE 同目录存在 HTML。
- API 成功响应保留 201；网页和 JS 为 200；未知路径 404；无效配置名或不存在的导入文件 400；`OPTIONS` 为 200。

| cmd | 行为 | 返回附加字段 |
|---|---|---|
| `获取所有配置名` | 列 `配置保存\` 下文件名（去扩展名），逗号连接 | `配置列表` |
| `保存配置` | 把当前 js 复制成 `配置保存\<arg>.js` | `是否刷新=是` |
| `删除配置` | 删除该快照 | `是否刷新=是` |
| `导入配置` | 替换当前 js → 重新 `configInit` + `configSyncAll(true)` | `是否刷新=是` |
| 其它任意 cmd | 当成配置项：`hashSet(cmd, arg)` + 立即落盘 | — |

固定返回字段：

```jsonc
  "推理耗时毫秒": "g.inferMsPrecise（同上受存活判据保护）",

```

### 网页参数与连接地址

网页通过同源 `/config.js` 初始化参数，服务端根据当前运行值生成带数字、布尔值及转义字符串的 JS。
配置文本中有空值或中文也不会破坏脚本语法。调参后立即保存，刷新网页即可看到已保存的值。
请求始终发送到 `location.origin + '/api'`，不会把局域网访客错误地引向其自己的 `127.0.0.1`。
`圣人自用.js` 继续作为本机配置文件，网页不直接加载该文件；旧 `主机IP.ini` 可以保留但不再影响监听地址。

## 4. 界面（纯 Win32，`Ui.cpp`）

窗口 `SagaAppWindow` / 标题「圣人视觉 C++ · 采集与推理 | 网页访问IP：实际地址」，客户区 1080×792。

| 300 | 复选框 | 实时显示（F1 等价开关） |

- 画板 640×640 等比显示原始帧 + 检测框（`小徽标` 标签：`类别 置信度`）+ 准星圈（`锁定范围`）+ 移动指示线。
- **状态栏**：`中心 W×H  采集 N FPS  推理 N FPS  <显卡名>  N ms`
  - 推理帧率双口径：**显示图片时**用实测 `g.inferFps`；**不显示时**用 `round(1000 / inferMsPrecise)`。
    这是用户要求的「显示脱节」，不要「修正」它。
  - 显卡名走 DXGI 动态查询 + `GpuIdTable.h`（PCI ID 反查真实型号）+ `GpuNameTable.h`（压短名），
    过长按像素宽度截断（`IsDBCSLeadByte` 防切半个 GBK 字），**ms 永不被挤掉**。
- **自动截图**：`运行目录\<模型名>\<毫秒时间戳>.jpg`，JPEG 95，节流 80ms。
- 启动时读取上次实时显示状态；有完整的成功采集记录时，异步恢复设备和格式。新版首次成功采集后建立恢复记录，无记录时不自动采集。旧版监控配置和“任意参数启动自动采集”的分支已删除；人手采集/训练子命令仍单独处理。
- 主程序启动一个隐藏的独立守护进程（同一个 EXE 的 `--watchdog` 内部模式）。它阻塞等待主程序退出，不轮询帧；非零异常退出后以 `--supervised` 模式重启，后续进程由原守护进程继续监督，不层层创建守护进程。正常关闭、零退出码或系统关机时退出守护进程。连续崩溃重试间隔从 2 秒逐步增加，最多 30 秒；不处理未退出的卡死。设备未就绪或恢复失败时显示错误，保留窗口供手动操作。

## 5. Makcu 串口（键鼠输出）

- 连接：`saga::makcuConnect(port)`，`port=0` 自动扫
  （描述含 `CH343` / `CH340` / `CH347` / `CP210` / `Silicon Labs` 的串口，并与 `DEVICEMAP\SERIALCOMM` 交叉校验）。
- 波特率探测：4,000,000 → 3,000,000（Ferrum）→ 115,200；落在 115200 且是 MAKCU 时会发 `BAUD_CHANGE` 再切到 4M。
- 命令：`km.move(x,y)`、`km.left/right/middle/side1/side2(0|1)`、`km.buttons(0|1)`、`km.echo(0)`、`km.version()`，
  一律追加 CRLF；**移动/按键走栈上缓冲，零堆分配，不逐条 flush**。
- 按键上报：部分固件在 `echo(0)` 后仍回显；按实际固件兼容裸字节及带前缀的按键报文。
  解析器兼容裸 mask、`km.<mask>`、`km.buttons<mask>` 三种形式。带前缀按键报文在 CRLF 处完成；命令 ACK 才等待 `>>> `，兼容旧捕获报文附带的提示符。独立的 mask 10/13 仍是合法按键组合，不作为文本换行忽略。
  另兼容实际日志中的 `km.buttons()` + LF（或 CRLF）+ 二进制 mask + CRLF + 可选提示符格式。只匹配完整头部，头部换行不产生按键；mask 必须为 0~31，完整尾部收到后才更新状态。
  协议异常或串口故障时，通过后台日志队列写入 EXE 同目录的 `运行日志.txt`，记录断开原因、可取得的错误码及异常附近少量十六进制字节；正常按键不写日志。
- `x,y` 超出 int16 范围（±32767）返回失败，不静默裁剪。
- `Makcu\cat\`（Kmbox/Cat 网络键鼠：AES + asio UDP）已编译导出 C API，但**应用层目前没调用**。
